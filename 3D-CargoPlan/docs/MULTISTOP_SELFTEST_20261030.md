# 工作台与多站装卸验收（2026-10-30 修订）

本记录替换此前的测试说明。此前“把未卸原货顺延到下一站”的行为已取消：不得私自改变目的站。

## 问题根因与修复

1. 框体弹窗仅有尺寸和空腔，侧栏却可编辑承重等约束。现在侧栏与 3D 浮层共用完整编辑器，所有货型均可进入，包含重量、方向、承重、件数、错位、落地、最大面朝下、混装和方向专用规则；有空腔时才显示空腔字段。
2. 旧多站清单把上一站“计划装入但失败”的货物继续下发成待卸任务。现在保留完整交付需求 `scheduledUnload`，实际在车待卸为 `plannedUnload`；上游提货失败归入 `cancelledDelivery`，不生成卸货操作。输入中凭空出现或重复交付的 ID 会被拒绝。
3. 原卸货搜索按单件解阻，阻止其他本站待卸货物参加解阻。增加本站联合卸货事务，允许待卸货物互相清路；倒货全部可恢复才提交，失败回滚。
4. 每一个结果先在独立模块逐步重放，校核货物存在、参数与实占尺寸、移出/装入通道、装入约束、每步承托、临时库存恢复和最终快照。失败会终止本轮，不展示为有效操作方案。
5. 3D 点击步骤现在显示该步操作前与操作后的真实车内状态，而非仅高亮整站快照。
6. 容器修改后会清理承托缓存；同数量替换及回滚会清理候选位置缓存。恢复基线和重新导入时清理旧待装区提示。

## 两类任务不能混为一谈

- **当前整柜／可行任务**：保留原柜所有货物、规格与规则；随机选择可直接卸出的货物，生成同规格补货至腾出的空槽，得到可行性证明。先固定题目，再交给通用求解器，使用这些已知空槽作为待验证候选；对比通用解和构造解后保留完整且操作数较少者。这是流程验证题，不能证明任意随机题都能解，也不代表全局最优。新货不继承原货 ID 专用的 W02 高度例外。
- **当前整柜／任意随机挑战**：卸货与补货需求先固定，随后搜索。既定满柜方案不一定支持随意补货；限时启发式也不保证找到所有存在的解。失败会如实展示、记录与解释。
- **六件练习**：从当前柜取小件样本，明确标注缩小题目，保留尺寸与约束，不替代整柜测试。
