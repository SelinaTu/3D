# v3 承托判据与工程核查

审计日期：2026-10-18。审计对象是 `model-v3-contract.json` 的显式 `supportCriterion: centroid-hull`，不是对现场承托或全局最优性的证明。

## 结论

本次核心变化只取消实体底面积至少 80% 被承托的比例下限。`validSupportGeometry` 仍同时要求真实底材面积为正、真实承托投影面积为正，以及实体重心投影处于这些投影形成的支撑凸包中。未声明该字段及显式 `area-80-centroid` 仍执行旧 80% 判据。

`canPlaceAt` 的增量路径与独立 `validateSolution` 的完整路径均使用相同显式判据。三轴 5 mm 几何间隙、玻璃架对零间隙、原始单件身份和尺寸、净空及特定 W02 高度例外、许可方向、空腔授权与完整嵌入、上件自身禁止错位、同源叠放、源顶部单件重量、累计顶部重量和件数、最大面积面朝下等限制未由此开关关闭。

v2 的 `offsetStackScope: item-only` 是此前单独记录的范围校准；v3 没有再次更改它。面积比例载荷分配、均匀密度重心、`pdf-clearance-projection` 的间隔传载关系仍是明确列示的建模假设。

## 跨模型与输入边界

- API 只接受 `area-80-centroid`、`centroid-hull` 两个枚举值；空串、其他字符串、null、数值、布尔、对象和数组均拒绝。该字段仅适用于 `villa-pdf`。
- 容器序列化规则必须与请求中的有效判据一致。不能把容器的 v3 声明当作 v2 验收证据，也不能在 v3 请求下省略声明以隐式换回旧规则。
- 提供请求配置时，独立校验从权威原始货物和请求配置重建规则；容器自报的较宽松判据不能覆盖请求。
- 未提供请求配置的独立校验仍拒绝非法序列化枚举；只有合法的显式规则才会用于该模式。

新增回归：`src/core/support-contract-validation.test.ts`；补充 API 回归：`src/server/input-validation.test.ts`。连同现有模型、实体几何及长短框宏测试，6 个测试文件的 64 项均通过；全 `src` lint 通过。完整生产构建和 HTTP 集成验收由主任务统一执行。

## 结果表述边界

`validation.valid: true` 与完整装载是两个条件。当前研究指标采用 `eligible = independentlyValid && complete`，未装清单非空的候选不能参与“已超过原 11 柜”验收，也不能因尾柜变小就算缩尾成功。相同柜子重新编号被物理布局及配货指纹排除；PDF 对比同时列原编号尾柜与排序不变的最小柜。

所有 v3 投影方案的校验范围为 `geometry-and-load-assumptions`。保持 5 mm 空气间隔而没有新增实物隔垫，不等于证明实际接触和传力；报告必须保留这一范围，不能将低比例承托的新宏称为现场承载已验证。

旧 `container-eight-v2-certificate/PROOF.md` 明确以 80% 为必要前提，并明确取消后失效；证明脚本新增显式前提断言，仅接受默认旧 80% 或显式 `area-80-centroid`，不接受 v3。其结论只限原第 8 柜固定配货及 v2，不能用于 v3 或重新分柜后的整体 11/10 柜判断。
