## 0. 执行摘要（给决策用）

1. **规则碎片化是真楔子**：同一柜货从「装箱」到「上路/上轨/上船」要同时满足 CSC 额定、SOLAS VGM、CTU 配载加固、目的国道路轴荷、中欧班列偏载偏重、木质包装 ISPM 15 等——**现有装柜软件大多只做几何利用率 + 部分重心/轴荷，很少做成「地区/港口规则包」**。港口侧用 **P0=22 / P1=35** 的 Port Pack 广度承接（见 §4.5），**不**编造每港独家 stuffing 法。
2. **罚款/拒装是可产品化的商业语言**：超限超载在美/欧/中/英处罚尺度与执法形态不同（罚款、卸载、记分、拒装船、调偏改载）；VGM 缺失/错误更多是**船公司/码头商业拒装与滞期**。Rules Pack 可并列输出「罚款/拒装风险提示」与「倒货工时成本」——**未来商业卖点，非法律意见**。
3. **执行缺口仍在**：竞品已红海于「Excel→自动排柜→3D→多站分组」；X 扩样（去重 ~1204）与官网核对一致——**缺逐站倒货可解释、异形工程约束证据链、可审计作业/机器人任务草案**。
5. **产品一句话**：把「货单 + 站点卸货 + 地区规则包（含风险提示）+ 业务约束」变成可检查的装载方案、逐站取货步骤与可审计作业/机器人任务草案——**不是又一个 3D 装箱器**。
5b. **司机侧扩展（v1.5）**：国内大车顺路平台痛在撮合质量与超载/拖欠；舱策以 **接单前 3D + 政策速查** 做并行工具（`CLAWHUNT_DRIVER_PLATFORM_PAIN_AND_PLAN.md`），**不**自建货源大厅。

### 1.1 问题

| 层 | 现状 | 后果 |
| --- | --- | --- |
| 规划 | Excel / 经验排柜仍默认；纸面能装、码头重来 | 工时、返工、错装赔损 |

| 异形 | 多数默认纸箱/托盘；悠闲等明示不做异形 | 工程柜（门窗玻璃架）空白大 |

### 1.2 机会（规则差异 × 规划赋能）

**强产品楔子（有公开依据）：**

- **VGM Method 2**：需累加货件+托盘+垫木+绑扎材+箱皮重——规划器可输出「VGM 草稿清单」（仍须船方法定流程与计量认证，产品不做认证）。
- **CTU Code**：重心居中、重不压轻、勿偏载集重、空隙填塞、危险品近门等 → 可做成可勾选规则包 + 违规解释。
- **道路轴荷地区差**：美 Interstate Bridge Formula vs 欧 96/53 轴荷总重 vs 中国 GB 1589 / 超限规定 → **同一柜重在不同路段/车型上「能不能上路」答案不同**，适合「区域 profile」。
- **罚款/拒装/调偏成本地区差**：同一超重在德州档位罚金、德国 BKat 百分比罚金、中国「卸载+按吨罚款封顶」、英国固定罚金梯度上答案不同；VGM 无证则**不得装船**——适合「风险提示 + 预估成本区间」模块（见 §4.4）。
- **中欧班列偏载偏重**：公开材料有横向 ≤100 mm、纵向按箱型限值、重心高等 → 相对海运柜规划是**可产品化的硬校验**（车站可能更严 → 待核实可配置）；发现后多为调偏/改载/延误成本（公开统一行政罚款表少 → 标待核实）。

**弱/需克制的楔子：**

- 「各港口各自一套神秘装柜法」——公开可核材料多为通用海关查验办法 + 行业留证拍照习惯，**不宜编造港别独家法规**；以可配置「口岸作业 checklist」承接。
- 「国内已全面柜内机器人」——证据指向堆场自动化强、柜内弱；叙事必须分层。

## 2. 定位

**一句话**  
CargoPlan（舱策）：面向外贸/货代/工程柜/多站配送的 **可审计装载与逐站装卸规划 Agent**——导入约束、按地区规则包校验、解释倒货与取舍，输出人可执行作业单与机器人可消费任务草案。

**不做 / 不宣称**

- 不宣称独家多站、独家 3D、独家轴荷。
- 不宣称已控制机器人或已通过法定计量/船级/公路执法认证。
- 不提供法律意见；规则包为**作业辅助与证据展示**，最终合规责任在托运人/承运人。

### 4.2 地区差异对「赋能货运规划」的结论

| 问题 | 结论 |
| --- | --- |
| 差异是否够做成产品？ | **够**。最强是：VGM 草稿、CTU 检查、美/欧/中道路轴荷 profile、铁路偏载偏重。 |
| 是否够当独家护城河？ | **不够单独当护城河**（EasyCargo 等已有轴荷；装箱大师有顺序/重心）。护城河 = **规则包 × 异形证据 × 倒货仿真 × Agent 审计** 组合。 |
| 港别差异怎么做？ | **Port Pack 广度**（P0→P1）+ 可配置 checklist + 客户录入；勿断言未核实的「某港禁止某某摆法」。MVP 3–5 港，Phase2 填 P0 再 P1。 |

### 4.3 待核实清单（规则）

- [ ] 各主要口岸（上海/宁波/青岛/深圳）是否有**公开可引用**的额外装箱几何/偏载书面标准（超出通用国标/海关办法）。
- [ ] 中欧班列各站点对偏载偏重是否统一执行公开限值，或存在更严地方执行（长安号文中已提示「车站可能更严」）。
- [ ] 中欧班列偏载偏重发现后的**调偏/扣车/改载费用标准**是否有公开价目（目前多为行业叙述，缺统一法定价表）。
- [ ] GB 1589—2026 对具体集装箱半挂车队型式批准切换日程与企业车队影响的细表。
- [ ] 欧盟成员国对 96/53 的国家例外与英国脱欧后道路限值对照表。
- [ ] Method 2 在中国主管机关认可流程与常用地磅 Method 1 占比（影响产品默认引导）。
- [ ] 美国各州超重罚金表持续更新（无联邦统一罚金表）；产品只引用「示例州」并强制选州。
- [ ] 国内主要船公司/码头对 VGM 迟交/错误的**现行附加费与滞期条款**（商业条款，非行政罚款）。

#### 4.4.2 产品功能：「风险提示 / 预估成本」与倒货工时并列

| 功能点 | MVP | Phase 2 | 商业化话术 |
| --- | --- | --- | --- |
| **Rules Pack · Risk Overlay** | 演示：选 CN/US-TX/DE/NL/UK/VGM/Rail 之一 → 超阈时弹出「法定/示例制裁摘要 + 来源链接」 | 州/成员国参数表、版本日期、客户私有费率 | 「装之前看见罚单与拒装风险，而不是过磅才知道」 |

| 玩家 | 公开状态 | 要点 |
| --- | --- | --- |
| **Dexterity × FedEx** | 2026-07 宣布在 Hagerstown Hub **扩大**自主拖车装载部署（多超试点） | 双臂 Mech + Foresight；按空间/稳定/速度规划放置；行业叙事：**装车比卸车难一个数量级**（媒体引述「100× harder」类表述——作叙事引用，非我方实验数据） |
| **Pickle / 其他** | 卸货为主；码垛/装车能力在路线图或伙伴集成 | 说明完整「装—运—卸」机器人链仍未闭合 |

**对 CargoPlan 的含义**：竞品装柜软件几乎不输出「机器可读装载序 + 设备包络」；当装车机器人变贵且稀缺时，**谁能提供合规且可执行的装序**谁更有集成话语权。

#### 5.4.4 共性技术难点（决定产品字段）

- 混 SKU / 无 ASN / 软包与异形；工程柜（门窗玻璃架）远超当前箱货机器人 envelope。  
- 装车需前瞻式稳定与空间规划（比「看见就抓」的卸货难）。  
- 软体夹具、多模态 VLA/世界模型在快速迭代——**规划软件应参数化能力，而不是绑死一家 OEM**。

#### 5.4.5 CargoPlan 路线图（未来价值叙事 · ClawHunt 商业化）

   ↓

| --- | --- |

#### 5.4.6 主流协议 + 双臂友好设计（→ 附录 **v1.2**）


**协议怎么选（不发明标准）**

| 需求 | 主流选择 | CargoPlan 做法 |
| --- | --- | --- |
| 任务下发 / WMS | REST 或 gRPC | 导出/推送 task draft |
| 事件与舰队遥测 | MQTT | 未来回执通道 |
| 门禁/输送线/PLC | OPC UA（Robotics TaskModule ≠ 装柜 schema） | 映射为 `preconditions[]` |
| AMR 舰队主控（欧） | **VDA 5050**（**非**双臂抓取标准） | 可选 `amr_order_ref` |
| AMR 共存状态（美） | **MassRobotics AMR Interop**（**臂出范围**） | 弱耦合 |
| 臂运动/任务层 OSS | **MoveIt 2 双臂组 · MTC · Pilz · ros2_control · BT.CPP**；或 UR/ABB/Fanuc；可选 cuRobo | **不内嵌**；draft 可选 `bt_skill_hint` / `mt_constructor_stage` |
| 柜内装卸任务 ISO | **公开检索稀缺** | 自建 schema 0.2 + disclaimer |

**双臂友好产品原则（规划层 · 有论文/OSS 依据）**

1. 显式 `frames` + 可选 `shared_workspace_envelope`。  
2. `sequence` + `preconditions` + 可选 `occlusion_order`（遮挡/DAG 依赖）。  
3. 可选 `arm_role` / `requires_dual_arm` / `sync_constraint` / `relative_pose` / `grasp` / `collision_envelope` / `regrasp_policy`。  
4. 超 profile 或异形 → `human_confirm`。  
5. SI + `schema_version`；UI「草案 ≠ 控制器指令」；安全标准（ISO 15066）≠ 任务语义。

**具身智能（v1.6）**：成熟货运落点仍是 VDA5050 / Open-RMF / OPC UA / ROS2 / GB/T 43047；LeRobot·OXE·openπ·OpenUSD 是**数据/策略/场景准协议**，可被伙伴映射，**不进 MVP 控机叙事**。柜内 stuffing 公开数据与标准仍稀缺。

**对竞品**：装柜 SaaS 几乎无上述契约 → Ops Draft 是未来集成话语权，而非今天控机卖点。

### 7.3 MVP（黑客松 48h）vs Phase 2

**MVP（对齐 `CLAWHUNT_HACKATHON_PLAN.md`）**

- 场景：固定 A→B→C，单侧柜门，20–40 件（含异形/箱形脱敏样例）。  
- 坏方案有遮挡 → 重规划后阻挡清单与倒货次数。  
- 改 B 站货量 → 重算 + 约束验证。  
- Agent：导入→确认→求解→校验→解释。  
- 导出：方案 JSON + 作业清单 + 任务草案字段。  
- Rules Pack：一页 CTU/VGM/偏载 **checklist** + **罚款/拒装风险提示示意**（引用公开档位，不做精确罚单）。  
- 机器人：task draft **schema 0.2** 样例（含 `frames`、一步 `relocate`→buffer、可选双臂 `sync_constraint`/`arm_role`）+ `equipment_profile_id`；UI disclaimer「非控机」。  
- 指标：同数据可重放；**不预设改善百分比**。

**Phase 2**

- 完整 CN/US/EU/UK axle + **Risk Overlay** 参数表与车型库。  
- 中欧班列偏载偏重计算与加固方案附件；调偏成本占位对接客户费率。  
- VGM Method 2 分项导出对接企业称重流程。  
- 设备能力 profile 库（Stretch 单臂卸 / 双臂装车类 / 人工 / 叉车…）过滤不可机装件；发布 JSON Schema。  
- 企业 API 异步求解、权限、审计包；task draft REST；可选 MQTT 回执与 `amr_order_ref`。  
- 1–2 家付费试点；与集成商联调仿真（ROS/OEM 翻译层，仍非控机）。
