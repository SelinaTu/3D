| 已验证能力 | 证据 |
| --- | --- |
| 异形约束装箱 | `sample-cargo.xlsx` 三表：门窗 / 玻璃架 / 辅材；方向、叠放、空腔、承重 |

**明确缺口（正是黑客松要做的）：** 多站点装卸顺序、通道/遮挡倒货、Agent 约束解释闭环、机器人可消费任务草案、商业化叙事与访谈证据。

## 二、产品一句话

**CargoPlan Agent**：把「货单 + 站点卸货需求 + 业务约束」变成可检查的装载方案、逐站取货步骤，以及供机器人/WMS 消费的任务草案——不只是排柜，而是服务未来装卸机器人的多点装卸规划。

## 三、主赛道建议（组队只能选一个）

| 主赛道 | 为何合适 | 风险 |
| --- | --- | --- |
| **商业化产品（推荐）** | 有真实工程物流样例、可讲付费痛点（倒货、人工规划时长、错装赔损）；Demo 同时展示 Agent 与 3D | 需当场说清 ICP、付费点、下一步验证，不能只秀算法 |
| Agent | Agent 工作流（导入→确认→求解→校验→解释）清晰；贴近 ClawHunt 平台气质 | 易被当成「套壳调 API」，须强调确定性求解器 + 可审计证据 |
| 3D | 已有三维回放与遮挡步进视觉冲击强；Tripo 等资源可加分 | 仅可视化不够，须绑定业务结果（少倒货、可执行作业单） |

**策略：** 报名主赛道选 **商业化产品**；Demo Day 叙事覆盖 Agent（决策链）+ 3D（可验证空间）+ 商业化（痛点与付费）。若队友强算法/Agent，可改主报 Agent，商业化作评委问答层。

## 四、对标与痛点（勿夸大独家）

| 竞品/现状 | 已有 | 我们的切入（待验证假设） |
| --- | --- | --- |
| EasyCargo 等装载软件 | 3D 装载、多站优先组、手动调整 | 中文复杂约束与**证据追踪**；逐站**遮挡/倒货解释**；人工改完后**再校验**；企业/机器人可审计任务 JSON |
| 人工 Excel + 经验 | 灵活但慢、难复盘、易漏约束 | 同口径可重放指标；约束来源可展示 |
| 机器人装卸（如 Pickle 等） | 末端执行 | 我们交付**上游任务草案**，不宣称已控机 |

现场痛点假设（访谈验证）：多卸点时「堵在门口要倒货」；规划耗时数小时；改单后无法快速复核；机器人/集成商缺标准作业序列接口。

## 五、48 小时 Demo（固定可讲故事）

**场景：** 已知顺序 A→B→C，单侧柜门；20–40 件异形/箱形货（从伊拉克清单抽一小集或新造脱敏样例）。

**基准：** 有明显遮挡的「坏方案」。  
**改进：** 重新规划后展示每站取货步骤、阻挡清单、预计搬移次数。  
**交互：** 改 B 站货量 → 重规划 + 约束验证。  
**导出：** 方案 JSON + 作业清单 +（可选）机器人任务草案字段。

**物理假设（演示必须写明）：** 离散矩形障碍、沿柜门直线平移、无机械臂体积/货物旋转；支撑与嵌套货须先安全移除。不能证明可行时报告原因，不虚构成功。

**Agent 闭环：** 结构化导入 + NL 限制抽取并标来源 → 用户确认 → 确定性求解 → 独立校验 → 自然语言解释取舍 + 3D 步进。

## 七、演示指标（诚实口径）

同数据、同模型、可重放。示例指标：柜/车数、完整性、逐站倒货次数、通道阻挡件数、校验通过率。**不预设改善百分比。** 伊拉克 11 柜结果仅作「我们做过硬约束装箱」的背景，不作为本 Demo 数字。

## 八、商业化一页纸（评委问答）

- **用户：** 工程物流调度、专线/零担、仓管、系统集成商  
- **愿付费点：** 少倒货工时、少错装、可审计方案、对接 WMS/机器人  
- **模式假设：** 按席位/方案订阅 + 企业 API + 实施；价格访谈后定  
- **下一步：** 脱敏单据 PoC；明确不控机、不做未验证动力学承诺
