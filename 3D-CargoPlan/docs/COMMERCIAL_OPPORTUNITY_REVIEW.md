# CargoPlan Agent：接单前可行性与逐站装卸规划

调研日期：2026-10-30。本文为产品方案与商业假设，不是已完成客户验证或已交付功能清单。

## 建议定位

面向门窗、家具及工程物流承运商，输入当前车厢货物状态、候选订单、取送站点和装卸设备，判断追加订单的几何及作业可行性，展示成本取舍，交付逐站装卸方案。先向有稳定SKU和固定线路的小型车队及专线企业收费，再探索货运平台与机器人集成商的接口。

创新应体现为“复杂规则与空腔关系贯穿接单、逐站卸货和设备适配”，不是把3D、Agent、多站点三个已有概念相加，也不声称算法或市场全球首创。

## 原始案例中的真实难点

依据现有源数据复核记录 docs/MODEL_CALIBRATION_REVIEW.md、docs/W02_ROW16_REVIEW.md：

| 原始需求 | 对产品的意义 | 市场证据边界 |
|---|---|---|
| 门窗16行W02外部顶部禁放，内部允许辅材或侧放框扇 | 实体、空腔、内载与外顶载需分别建模；不能只用外包长方体 | 悠闲装箱公开写近似立方体货物；未找到三家对这套具体组合的完整支持说明，不能推断全部不支持 |
| 门窗21行短框孔仅允许辅材；23行长框孔允许辅材/侧放框扇 | 空间不是任何货物均可用，余量要随类别和方向变化 | 是本批确实存在的需求；行业发生率及支付意愿仍需客户验证 |
| 分姿态承重、严格小于120kg、同源自叠、层数、最大面向下 | 需要带条件及出处的规则，不能被统一字段吞掉 | 方向/承重/堆叠本身已很常见，不能单独当作差异 |
| W02侧放高2560、通常建模上限2500、备注给专项例外 | 先区分计划上限与实际柜内/门洞硬限；错误题目应先报告 | 规则一致性检查机会，不是突破物理限制的创新 |
| 原说明中间隙与实际承托关系存在模型边界 | 现场设备、隔垫、梁强度等需补足，不能由LLM凭空假定 | 当前方案不等于实物装卸验证 |

原始文件没有多站订单、停靠时间、货物抓取面或机器人型号信息；这些属于新增业务输入。将原案例改造成三站样例时必须标成演示扩展，不能称为原始运输事实。

## 竞品与证据

1. 悠闲装箱公开支持多仓装货/多目的地卸货顺序，会员权益页同时写明其算法针对近似立方体，暂不支持其他异形货物。这支持研究空腔框体这一细分需求，不证明所有企业定制产品都不支持。
2. packVol已提供分姿态规则、叉车搬运相关控制、多站纵向顺序、保留既有布局的增量装载。说明“约束多、能增量、多站点”都不是行业空白。
3. 满帮官方说明其车货撮合、货运经纪和交易生态；这些公开材料不能用于认定其内部或合作产品没有三维可行性能力，更不代表我们已有平台接口或订单授权。
4. Boston Dynamics公开资料说明Stretch有自主感知及实时规划能力，不依赖预先提供货单。其公开箱式货物能力不能直接套用本批大尺寸、51kg的W02门框；须逐设备确认尺寸、载重、夹具及抓取要求。新产品应提供跨订单/跨站决策，不以“机器人缺少感知规划”为商业前提。

## 演示场景

固定SKU模板及三站线路，原有长框/辅材作为脱敏几何参考，使用实际适配车辆或明确的示例尺寸，不沿用未核实的高度豁免。生成候选订单三种结论：

- 订单A：重量和总方数都合适，合法摆放方案也找到，逐站动作通过当前简化验证；展示接单后的预计增量收益。
- 订单B：静态可以嵌入框孔，但提早卸货时受到框及其他货物阻挡，需额外搬移或改变摆放；展示取舍，不把所有嵌套都判为无法卸出。
- 订单C：重量、尺寸或指定设备能力有确定冲突，指出来源；只是限时搜索失败时应写“未找到可行方案”，不能写“物理无解”。

步骤回放须逐次检查占位、通道、支撑依赖和剩余货物；机器人夹具、关节运动、运输动态及实物强度仍在简化模型之外。第一次只做固定线路/单柜门/少量标准SKU，不同时实现全国路线优化和通用机器人控制。

## 功能结构

Agent负责规则抽取、冲突解释、调度工具与结果沟通；确认后的规则交确定性几何及规划器执行。以“节点+关系”表达货物的支撑、嵌套、遮挡和取送依赖。设备能力采用版本化配置：人工、叉车、箱式机器人等分别描述支持货型、重量尺寸、抓取/插叉条件；缺少数据则返回需确认。

接单评分须以当前完整计划为基线，计算候选订单新增的绕行、停车、装卸和搬移费用。新增收入减新增可核实成本为估算贡献，不把方数最大化等同利润最大化。货损缺少数据时单列风险及待确认项，不给伪精确概率。

每个到站状态重新评价承重、平衡、支撑和可操作性；公路车轴载等需对应车型数据，不能只用集装箱总载重代替。实际运输产生位置偏差后，任务状态必须由扫码/人工/感知确认更新，旧计划不能直接作为实物状态。

## 商业路径与验证门槛

首批付费人：门窗/家具工程物流的小车队调度负责人、专线经营者或制造企业物流负责人。其收益与返工、规划耗时和额外车辆直接相关；司机可为使用人，但不先假设每位司机会订阅。机器人厂商和全国平台作为后期合作方，需要接口、试点和采购验证。

先做脱敏订单/CSV或企业授权接口的独立辅助工具，不依赖抓取平台订单或自动抢单。试点可用按月调度工具或按次审单收费；机器人企业集成另计实施费。价格未验证，不宣称已有收入。

建议访谈至少5家目标客户，取得至少3家可回放业务样本，分别记录人工耗时、现场搬移、临时加车、货损及装卸设备现状。以真实运输回访验证，不只比较装载率。可用明确的假设例子测预算：每月100单、每单净节约80元，对应每月8000元价值；这些数字仅是访谈测算，不是市场统计或承诺。

继续商业投入的门槛：多个客户反复出现同一类问题；通过同约束的竞品试用发现可重复差异；至少一个客户愿意进行有费用的试点；单客户节省高于订阅、数据维护、人工确认与实施总成本。若只能靠每单人工定制，不应按可规模化SaaS估值描述。
