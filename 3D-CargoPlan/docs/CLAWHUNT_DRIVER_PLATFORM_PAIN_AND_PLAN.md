## 0. 一句话结论

**痛点结论：** 六类 App 的红海都在 **车货撮合 / 导航找货**；司机侧高频伤是 **低价·倒货·黄牛、超载订单与拒单扣分、运费拖欠与线下失联、装卸等待算不清账、返程空驶、信息碎片化**——公开报道与平台自救公约高度重合。用户排序把运满满/满帮放首选、货拉拉/滴滴货运放同城补充，**方向大体成立**；但「省省」已并入满帮系叙事，鱼泡网本质是 **招工找活** 而非干线配货主平台，需降权。

**我们的楔子：** 不做第二个满帮。做 **接单前的装载·合规·政策证据层**——导入货单尺寸重量 → **3D 装配预演** → 轴荷/超载/品类风险提示 → **港口·口岸·园区政策速查（Port Pack）** → 导出装载图/证据包给货主或安检 → 可选多卸点顺序。与撮合 App **并行**，帮司机回答：「这单顺路值不值得接、装不装得下、会不会超、到港/园区会不会踩政策雷。」

### 1.1 用户「顺路外快提醒」与公开证据对齐

| 用户提醒 | 公开证据对齐 | 产品落点 |
| --- | --- | --- |
| 不能超载；危禁品不接；营运证/保险；捎货也算营运 | 央视：超载单可发、拒载可能扣分；恳谈会：危化品误运被司机代表点名 | **接单前**轴荷/品类 checklist；危品硬拦截提示（非许可代办） |
| 算清高速、时间、装卸等待，勿亏本低价 | 春风行动/低价阻断；省省守则有等待费标准 | **简易利润粗算**（油费/过路费字段手填 + 等待假设） |
| 优先平台担保（满运宝等），少私下微信 | 南都线下失联；满运宝官方担保叙事；司机守则：线下未付平台不垫付 | UI 默认「走担保」；证据包便于纠纷举证 |
| 卸货前就订阅返程方向 | 各平台均有订阅/推送叙事；行业常识 | **与撮合 App 并行**：订阅仍在满帮等完成；我们在「意向单」上做预演 |

## 2. 司机侧痛点聚类

| 聚类 | 表现 | 证据强度 | 现有平台覆盖 | CargoPlan 能否补 |
| --- | --- | --- | --- | --- |
| **A. 货源质量：低价 / 倒货 / 黄牛** | 一货多倒压价；信息费盘剥；假货源放空 | ★◆ 恳谈会、春风行动、罗戈倒货 | 平台治理中，未根除 | **弱直接**；可做「价 vs 里程/时间粗算」辅助拒单 |
| **B. 返程空驶** | 卸完再找货晚半拍；空等物流园 | ◆ 行业报道；各 App 订阅功能 | 订阅/推送是主战场 | **弱**；不自建货源池 MVP |
| **C. 超载与拒单惩罚** | 小车价拉大货；备注不全；拒超载被扣分 | ★ 央视实测可下超载单 | 提示线有，强制拦截不足 | **强楔子**：车型 profile + 重量/尺寸 → 超载风险提示 |
| **D. 品类合规（危禁品）** | 油漆等危化误运；普通车拉违禁 | ★ 恳谈会点名危化品误运 | 货主核验加强中 | **强**：品类标签 + 拒接建议 |
| **E. 运费拖欠 / 线下失联** | 卸货后货主失联；私下转账 | ★ 南都；◆ 倡议书/自律公约 | 满运宝等担保；线下仍漏洞 | **中**：证据包（装载图+照片 checklist）辅助维权，不垫付运费 |
| **F. 装卸等待与算账** | 压车、等待费扯皮；亏本顺路 | ○ 省省等待费规则；司机常识 | 规则有、执行靠协商 | **中**：等待/倒货工时粗算（与主方案倒货指标对齐） |
| **G. 装不下 / 装错 / 二次倒货** | 方数虚报；多卸点埋货；园区拒收重装 | 主方案 X/竞品结论 + 车队常识；**司机侧公开量化少 → 待访谈** | 撮合 App **几乎不做 3D 规划**；装箱软件面向货主/货代 | **最强楔子**：3D 预演 + 多卸点顺序 + 导出证据 |
| **H. 港口 / 口岸 / 园区政策盲区** | VGM、进港、查验拍照、限行限重与目的港轴荷 | 主方案 Port Pack / 罚款附录 | 导航有限行；**少有目的港/口岸装载政策包给司机** | **强**：Port Pack 速查（只写可溯源 stub，不编造港法） |
| **I. 信息碎片化** | 多 App 切换；电话确认尺寸重量；无统一装载图 | 使用路径常识 + 沙师弟「导航+配货一体」叙事 | 各做一块 | **中**：一单证据包打通「货主↔司机↔园区」 |
| **J. 金融/会员摩擦（旁支）** | 会员费、行为分、小贷投诉 | ◆ 行业报道；○ 黑猫 | 平台自身问题 | **不做**；避免金融产品 |

**证据强弱小结：** A/C/D/E 有权威报道支撑；G/H 与 CargoPlan 能力最贴但 **司机侧量化待访谈**；B 是满帮护城河，我们不抢。

## 3. 核心产品方案：「大车司机侧」舱策工具

### 3.1 命名提案

| 候选 | 语气 | 备注 |
| --- | --- | --- |
| **舱策司机助手**（推荐） | 中文直白，对齐「舱策」品牌 | 路演/司机口语友好 |
| **CargoPlan Driver / 舱策顺路预演** | 强调「预演」而非「抢单」 | 英文对外、黑客松可用 |

对外一句话：**接单前装得下、超不超、政策雷不雷——3D 可验证的司机侧装载助手**（并行满帮等，不替代撮合）。

### 3.2 目标用户

| 角色 | 车型场景 | 核心诉求 |
| --- | --- | --- |
| 干线个体司机 | 6.8 / 9.6 / 13 m 高栏、厢式 | 回程不空、不超不亏、少被园区/货主扯皮 |
| 车队长 / 车队调度 | 多车同型 | 统一车型库、批量预演、证据归档 |
| 专线小老板 | 固定线路 + 零散整车 | 多卸点顺序、给货主发装载图 |

**非目标（MVP）：** 自建全国货源大厅；替司机垫付运费；控机器人/自动驾驶。

### 3.3 核心闭环（MVP）

```
[意向单入口]
  手动录入 / 粘贴货主微信描述 / 拍照 OCR（后期） / 从满帮等「复制货源字段」手填
        ↓
[车型 profile]
  6.8 / 9.6 / 13 高栏·厢；内长宽高、额定载重、轴组（可选粗）
        ↓
[3D 装配预演]  ← CargoPlan / 舱策核心
  能否装下 · 重心示意 · 多票拼载 · 遮挡/卸序（有多卸点时）
        ↓
[风险提示]
  超载/超方 · 品类（危禁） · 简易利润粗算（手填油费过路费）
        ↓
[港口·口岸·园区政策速查]  ← Port Pack 子集
  目的港/口岸 stub：VGM 提醒、查验拍照 checklist、道路轴荷地区 profile 链接
  （不编造「某港禁止某摆法」；细节见 CLAWHUNT_PORTS_P0_P1.md）
        ↓
[导出证据包]
  3D 图 / 步骤清单 / PDF·图片分享给货主或园区安检
        ↓
[可选] 多卸点顺序优化 → 倒货次数示意（与主方案 Hackathon 对齐）
```

**与满帮等关系（写进产品原则）：**

- MVP = **并行工具 / 浏览器或小程序**，司机继续在运满满/货车帮/沙师弟找货。  
- 不宣称「我们货源更多」。  
- 远期可谈：**Open API / 小程序插件 / 分享链接嵌入**（需对方商务，**待核实**）。  
- 网络效应承认：撮合是红海且满帮极强；我们卖的是 **装载与合规证据**。

### 3.4 竞品空白矩阵（司机场景）

| 能力 | 满帮系 | 沙师弟 | 物通 | 货拉拉/滴滴 | 装箱大师/EasyCargo 等 | **舱策司机助手** |
| --- | --- | --- | --- | --- | --- | --- |
| 干线货源撮合 | ✓ 强 | △ | △ 信息 | ✗ 偏同城 | ✗ | ✗ MVP 不做 |
| 货车限行导航 | △ | ✓ 强 | △ 地图找园 | △ | ✗ | ✗（可链出） |
| 担保交易 | ✓ 满运宝等 | ✓ 叙事 | △ 弱 | ✓ 平台结算 | ✗ | ✗ 不垫付 |
| **接单前 3D 装载给司机** | ✗ 公开主打 | ✗ | ✗ | ✗ | ✓ 偏货主/货代·桌面/分享查看 | **✓ 主打** |
| **港口/口岸政策速查（装载相关）** | ✗ | ✗ | ✗ | ✗ | △ 少 Port Pack 广度 | **✓ Port Pack 子集** |
| 轴荷/超载接单前提示 | △ 发单提示弱 | △ 路上限重 | ✗ | △ | ✓ EasyCargo 等偏规划端 | **✓ 车型 profile** |
| 多卸点倒货可解释 | ✗ | ✗ | ✗ | ✗ | △ 分组预防 | **✓ 对齐主方案** |

> 诚实边界：EasyCargo / 装箱大师等已有 3D 与移动端查看——**不宣称全球独家 3D**。差异是 **司机接单决策闭环 + 中国大车车型库 + Port Pack 政策速查 + 与顺路撮合并行**，而非「又一个装箱器」。

### 3.5 MVP / Phase 2 / 路演叙事

| 阶段 | 范围 | 成功标准 |
| --- | --- | --- |
| **MVP（ClawHunt 可演示）** | 3 种车型 profile（6.8/9.6/13）；手工货单 → 3D 能否装下；超载/超方提示；**演示港 3–5** 政策 checklist；导出分享图；多卸点 1 个坏→好对比 | 评委/司机 90 秒看懂「接这单前先预演」 |
| **Phase 2** | 车队长多车；OCR/粘贴导入；利润粗算模板；P0 Port Pack 填表；品类危禁库；等待/倒货工时；与 1 家车队试点 | ≥1 付费或深度试用车队；节省可口述 |
| **后期（可选）** | 撮合平台插件商务；园区/货主只读链接；机器人任务草案（规划层，见双臂附录）——**仍非控机** | 集成意向，非装机量吹牛 |

**ClawHunt 路演 30 秒加一句：**  
「满帮解决有没有货；舱策解决这货装不装得下、超不超、到港会不会踩政策——3D 可验证，给司机和货主同一份证据。」

### 3.6 商业化草图（司机侧）

价格不预设；门槛同主方案：可回放样本、与竞品差异可重复、节省 > 成本。

## 4. 合规与产品红线

1. **不鼓励超载**：超载风险提示是为了 **拒单/改车型**，禁止「如何瞒过称重」任何指引。  
2. **危禁品**：仅提示「可能需资质/禁运」，**不**提供伪装运输建议。  
3. **营运与保险**：文案提醒捎货仍属营运；产品 **不**代办证件。  
4. **非法律意见 / 非罚单计算器**：罚款区间引用公开规定并标来源；UI 固定免责声明（对齐主方案 §7.5）。  
5. **不编造港别独家装柜法**：Port Pack 只挂可溯源 stub + checklist（见 `CLAWHUNT_PORTS_P0_P1.md`）。  
6. **不替代担保**：引导走满运宝等平台担保；我们不做资金存管。  
7. **不夸大**：不宣称独家多站/独家 3D；不宣称取代满帮网络效应。  
8. **隐私**：货单与车牌等默认本地/加密；不做金融放贷。  
9. **机器人**：司机产品与柜内机器人解耦；任务草案仅后期可选脚注。
