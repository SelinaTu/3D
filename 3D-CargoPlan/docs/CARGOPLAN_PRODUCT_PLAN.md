# CargoPlan 舱策 · 海陆运输作业智能体

> v7.0 · 2026-10-30 · 开工前产品评审稿
>
> **愿景：海陆运输作业智能体：用一份货物计划贯穿陆上多站集散、港口通关与海运装箱，统一处理异构货物装配、装卸顺序、政策费用与加固要求，并输出人和机器人都能执行的协议。**
>
> 本版采用你的愿景原文。长期目标覆盖海陆全程；首发继续陆运优先，服务运输公司与独立司机，同时交付集装箱装配、通关/政策辅助及可校验任务契约。范围建议待本轮评审，不据此启动交易、公开数据或接入真机。

## 01 本轮评审结论：愿景、首发和已定边界

**产品帮助用户作决定、组织作业并处理变化：哪些货能一起运，按给定站点计划以什么顺序装卸，哪些条件未满足，以及下一步由谁处理。** 3D装配、站点计划、政策、加固和执行协议围绕同一货物计划连接。

| 层次 | 本轮定位 | 不再混用的概念 |
| --- | --- | --- |
| 愿景 | 海陆运输全程的一份货物计划 | 不是所有阶段都使用相同坐标、车辆或执行者 |
| 首发用户 | 运输公司/调度与独立司机，仓库协作 | 货主提供数据；报关/设备人员只看各自任务 |
| 首发核心 | 陆运多站＋异构装配＋逐步作业校验＋一次改单 | 车型／柜数、装卸动作与可卸性分别比较 |
| 海运与通关 | 集装箱装配、单证/条款/状态辅助、人工确认 | 船期工具、海关放行、VGM核实和箱内几何互不替代 |
| 人与机器人 | 对象中心任务契约、混合执行者及回执语义 | 首发不接真机；模型通过不自动获得设备执行批准 |
| 平台方向 | 从自带订单助手走向授权走廊协作 | 自建全国货源、撮合交易与承运业务另行立项 |

一期已确认：客户导入Excel并输入站点计划，不做道路路线规划。建议交付一条可验收闭环：**一份货单→客户输入多站计划→3D逐步作业→异常重算→集货交接/海柜装配→通关和加固待办→人工单与任务包。** 通关与海运步骤按实际业务出现，不要求每趟国内车次都挂上海运页面。

## 02 面向谁，解决哪些痛点

| 人群 | 反复发生的决定/困难 | CargoPlan提供什么 | 谁更可能购买/提供数据 |
| --- | --- | --- | --- |
| 运输公司、小车队调度/专线经营者 | 多单多车怎么组合；改站序、换车、插单后要反复核对 | 订单/车次看板、站点与布局联动、动作代价、司机确认、版本 | 公司/调度主管；能协调仓库与合作司机 |
| 独立司机/车主 | 一单顺路货是否装得下、卸得出，是否值得接 | 一车手机入口、模板、候选评估、分项成本和逐站清单 | 司机使用，个人付费或公司提供，需试点验证 |
| 仓库、装卸班组、货主物流 | 包装数据不准、计划靠口头交接，少货/错放后难追溯 | SKU与包装模板、装载步骤、扫码/人工回执、偏差反馈 | 作为协作方提供测量和真实装载状态 |
| 出口物流/货代及受委托报关人员 | 同一票货在装箱、单证、进港与申报中重复录入，条件更新难核对 | 身份映射、装箱清单、资料缺项与官方状态来源、责任待办 | 首发海运协作方；不要求司机独自承担报关 |
| 自动化/机器人集成商 | 业务计划没有表达接近、承托、能力和异常条件 | 可校验任务图、执行者档案、证据与回执接口 | 后续伙伴；真实设备价值需独立试点 |

### 痛点归属要清楚

- **直接解决：** 所选货型下的装载/逐站拆取复核、规划版本一致、改单影响和可追溯作业单。
- **辅助改善：** 额外搬移与时间/费用判断、条款和单证缺项、交接与货损争议的事实记录。实际能减少多少要测量。
- **不能靠本产品直接解决：** 全国货源供给、低运价与黄牛治理、运费拖欠、海关是否放行、货物工程强度和设备安全批准。

成熟平台已经提供找货、路线推荐、顺路拼单或装载工具。我们的购买理由必须由具体任务证明：**减少用户总操作和返工，同时让计划变化后的条件与代价可见。** 复杂规则真实存在，不等于司机侧的发生频率和付费意愿已验证。

## 03 “一份货物计划”到底统一什么

统一货物身份与版本，不强行统一所有空间。订单、物件、包装、托盘/载具、车辆、集装箱、运输段、站点/设施、执行任务分别建模，保留包含关系与交接。

| 数据/事件 | 必须保留 | 例子 |
| --- | --- | --- |
| 物件与包装身份 | source/order/cargo ID、包装版本、数量/质量和来源 | 包装变化不静默覆盖已批准尺寸 |
| 运输段与装载单元 | 车次/站点、仓库、柜号/封志、关联货物集合 | 国内配送部分完成，出口子批在集货仓换装海柜 |
| 坐标与状态 | frame/单位、计划位姿、已确认实际位姿及时间 | 同一件从车厢转仓库再入柜，位姿和frame都改变 |
| 规则与责任 | 适用对象/条件、来源、版本、确认人 | 货物禁触面、道路限行、船司条件分别有范围 |
| 任务依赖 | 谁先完成、需要哪种能力/资源、预期状态变化 | 先移出阻挡物，交付目标，再回装并重新固定 |
| 证据与费用 | 计划版本、输入指纹、工具结果、分项参数与实际记录 | 重新规划不覆盖旧版；估计与实际分开 |

首发保持件级ID与数量守恒，支持明确的整组搬运/交接。拆包、拆托、合包等改变包含关系时需显式事件；未实现的转换报告“超出范围”，不凭空产生或消失货物。

海运封箱后转船默认搬整柜，保留箱内状态；明确开箱查验/拆拼箱/换装时才改变内部货物。通关记录与装柜确认、码头放箱/放货、船司接受状态分别记录。

## 04 首发交付包：哪些必须做，哪些后置

| 交付包 | 首发必须产生的结果 | 明确边界 |
| --- | --- | --- |
| P1 货单、包装与资源 | 导入规定模板，件级ID、缺项、一个真实车型/门洞、站点/堆区、版本 | Excel是入口；不先做全量ERP或任意CAD |
| P2 陆运候选与接单判断 | 客户输入站点及顺序，计算车柜分配、装载与装卸；可输入业务费用参数 | 一期不做道路路线规划；不生成虚假实时路线/运价 |
| P3 三维装配与逐步校验 | 静态几何/规则、每步支撑筛查、简化进出通道、本站拆取和余货 | 限定车辆模式和刚体模板；不把简化筛查称完整力学 |
| P4 人员/设备条件 | 人工、叉车档案及候选分配；未满足/未知项可见 | 人工同样受能力限制；不默认人工能搬一切 |
| P5 现场与改单 | 同版手机单、少货/错放/无堆区反馈，锁住已完成状态后重算 | 首发一种可复验变更，之后扩展 |
| P6 海柜与通关辅助 | 同一货物的集货/入柜映射、装箱资料、精选条款与通关状态来源 | 不自动申报/订舱；不以本地按钮冒充官方放行 |
| P7 加固任务 | 规范货物加固需求与来源，列人工确认提醒 | 不自动规划绑扎作业或计算强度 |
| P8 任务契约与复盘 | 0.3草案、格式/语义校验、人工单、模拟消费者和回执反例 | 未通过设备检查时不标可下发真机；不控机 |

**后置：** 全国公开撮合、资金/承运业务、全球实时政策与船期、完整报关申报、自动加固工程设计、真实机器人仿真/联调、学习型装箱训练、任意异形扫描建模。

首发P1—P8是建议交付包，具体货型/模型/海运深度由第13章评审决定。不能通过“未评估→默认通过”压缩工作量。

## 05 可以直接评审的体验主线

**建议业务样例：** 一辆配送车依次到A、B和集货仓H；A/B交付后，剩余出口子批在H入仓交接，再装海柜并准备进港资料。该样例包含真实的陆上逐件作业和换装事件，封柜后不会在中转港逐件卸货。

| 页面/步骤 | 用户在做什么 | 必须拿到的结果 |
| --- | --- | --- |
| 1 建立计划 | 公司导入订单，司机选车辆/已有状态 | 缺项定位到货物；展示数据来源与已定/未知条件 |
| 2 看候选 | 导入货单及站点计划 | 核对站点顺序、待运货物与未填写字段 |
| 3 货单＋3D审阅 | 点B站目标，查看阻挡、支撑、进出路径、临时区 | 逐步播放与每步校验一致；不能动画穿梁 |
| 4 确认执行者与加固 | 选择人工/叉车；查看货物加固需求 | 明确能力匹配、加固需求和待人工确认项；不编设备额定值 |
| 5 修改现场条件 | 把“B站无临时区”或一件包装尺寸修改 | 新版本与冲突原因；已完成动作不被重写 |
| 6 集货与海柜 | H仓确认交接，把出口子批映射到柜内 | ID/数量守恒，包装/坐标改变有事件；海柜装配同样校验 |
| 7 港口/通关工作单 | 出口物流打开条款、装箱资料和状态 | 缺项、来源、责任人与下一步；VGM/海关/码头状态分开 |
| 8 人工作业单/任务包 | 导出同版人工单与0.3数据；模拟能力不匹配/回执偏差 | 依赖/资源/能力错误被拒；真实与模拟回执明确区分 |

首个体验规模建议一车4～5站、20–40个物理单元、两种基础包装加一种复杂模板、一处临时区和一次改单；海柜装配是同计划中另一段任务。用户无海运业务时只使用陆运流程。

首发界面建议“公司网页工作台＋司机手机页”，货物列表、3D与本站任务并列。Agent提取/补问/调用/解释，规划与校验工具给出位置、动作、载荷与指标。模型或外部接口不可用时可展示标注的缓存；输入变化必须重算或返回未完成，不能只改结果数字。

## 06 吸收附件：把可执行性前移到规划

附件中的E1—E5作为检查维度采用；它们构成分层验证框架，**不能写成机器人真实可执行的充分必要条件**。实际还依赖感知、摩擦、夹具、控制、环境与设备验证。

| 检查 | 产品判断与首发方法 | 不代表什么 |
| --- | --- | --- |
| E1 序列支撑/稳定 | 对放置/移出后的每一中间状态和余货做支撑、重心/载荷筛查；假设有来源 | 支撑比例/重心投影不是完整静力、抗滑或运输动力学证明 |
| E2 接近与撤出 | 在选定尾门模式内检查货物/已声明工具包络扫掠与门洞、梁、已装货冲突 | 不等于机械臂逆解、叉车转弯或人员作业安全仿真 |
| E3 搬运/夹持匹配 | 对执行者核对载荷、姿态、叉孔/可接触面、所需能力；缺项记unknown | 尺寸/重量阈值不能单独推算“可由机器人搬” |
| E4 多站可取 | 取送先后、阻挡/支撑依赖、移出/回装、堆区占用和数量守恒 | 分组/静态终点无碰撞不能替代动作过程 |
| E5 容差 | 声明测量/放置余量；有实际容差后对关键参数做扰动检查 | 单一固定间隙或有限采样不证明整个±δ范围鲁棒 |

候选生成与交付前复验分开；复验使用固定输入、规则版本和动作日志，不复用求解器的“成功”标签。支撑件增加可能改变可行性，不能无条件缓存“某子集不可行→所有超集都不可行”。[3L-CVRP研究](https://arxiv.org/abs/2402.14868)。

同一动作可由人工、叉车或未来机械臂承担。可行性取决于货物、动作、执行者、设备/场地、当前状态与规则版本；不只是一个货物属性。首发给定人工/叉车候选并允许确认分配，不承诺同时优化完整多执行者协同与运动。

检查结果采用`pass / fail / unknown / not_applicable`，附方法/输入/证据。`simplified`和`sampled`是检查方法标签，不能混在结果里当作pass。

## 07 等级与执行资格：消除附件中的矛盾

附件首发路线图只做E1/E4却宣称L2，而其L2定义要求E1/E2/E4。本版修正：**没有E2就只交付已完成检查的结果，不能标L2。**

| 等级 | 本版含义 | 所需证据 |
| --- | --- | --- |
| L0 未完成基础验证 | 数据不足、尚未评估或基础检查失败，各自保留状态 | 缺项/失败原因，不能等同“只能人工” |
| L1 静态模型通过 | 本版声明的终态几何、支撑/载荷和货物规则通过 | 输入与假设、校验报告；不能声称顺序可执行 |
| L2 简化作业模型通过 | 本版E1/E2/E4对动作序列通过；E3/E5等其他维度另列 | 选定动作模式/执行者上下文、逐步日志、余货校验 |
| L3 特定设备仿真通过 | 伙伴对特定设备与场景验证必要检查 | 仿真/设备/profile版本、结果与覆盖范围 |
| L4 特定现场验证 | 指定条件下真实执行有有效回执 | 实际状态、偏差、时间、设备与责任记录 |

层级、能力匹配、是否批准执行是不同字段。L2同时存在“机器人夹持未知”是允许的，但此时`device_release=blocked`；人工/叉车也要完成其必需条件和现场确认。未知不是失败，失败也不能仅“降级”后继续自动执行。

等级按任务、目标profile、模型和版本出具。方案摘要列出分布、阻断任务与适用范围，不把混合执行者简单压成一个“机器人占比/最低等级”。一个任务通过L4不使整票货自动获得L4；计划变化后只继承仍有效且有相同依据的证据。

## 08 0.3对象中心契约：本轮的具体建议

**建议批准0.3草案方向；当前尚无已发布0.3 Schema或设备兼容性。** 0.2历史样例保留，迁移有报告，版本不兼容时拒绝或显式转换。

| 层 | 必须表达 | 首发验证 |
| --- | --- | --- |
| Core | plan/revision、cargo/task/stop/leg身份，frames/单位/起止位姿、对象约束、依赖/前置条件、资源引用、必需能力、检查报告与批准状态 | Schema、唯一ID/引用、DAG、单位/坐标、依赖与库存/资源检查 |
| Profile | 执行者候选/分配、载荷/工具/可接触面/工作范围/容差、来源和版本；Core显式引用 | 必需能力满足；缺实际规格时保持unknown并阻断相应执行资格 |
| Adapter | BT/MTC技能名、VDA5050关联、OEM调用与具体设备约束 | 独立版本/命名空间；首发只做一个模拟消费者 |

Core以`keep_upright`、禁触面、承托、共持需求等对象约束表达业务。设备侧根据抓取与标定求末端关系；`relative_pose`不能无损改名为对象约束，旧值若有可靠来源要连同设备语义保留/显式迁移，未知值不编。

DAG是任务依赖的权威，`sequence`仅为显示或一次拓扑序。可选hint可忽略；必需能力、profile和必需扩展不得忽略，未知时拒绝该设备消费。去掉Adapter后Core仍可格式校验，不代表设备已具备执行条件。

### 回执闭环必须完整

每次回执绑定plan/revision、task与attempt、执行者/profile、时间、坐标系/单位、实际位姿或明确未知、结果和证据。重复回执幂等，旧版/错任务回执不能更新现态；模拟回执标`execution_mode=simulation_only`，与生命周期分开。

回执缺失时阻断依赖该状态的后继任务；不自动阻断所有无关并行任务。偏差或环境变化触发复核，已完成动作保持，剩余步骤按实际状态生成新版本。即使偏差在容差内，也要核对其他前置条件，不能只凭一个数值自动放行。

“人机同序”指共享货物、业务依赖和计划版本；人工与设备可以细化成不同动作粒度。共持双臂载荷用有来源的协同规格，不能按两个单臂相加；同步开始也不证明持续共持或防撞。

## 09 货型、车辆、执行者与数据门槛

| 对象 | 首发建议 | 后续/门槛 |
| --- | --- | --- |
| 货型 | 包装箱/托盘单元＋一种有依据的框孔/长件模板 | 圆柱、防滚、任意设备、危险品、冷链等各自专项 |
| 车辆/装卸 | 车型与集装箱可自定义；Demo选一个有实测内廓、门洞、载荷和外廓的样例 | 尾装、侧开/翼开、高栏、平板、吊装等按模型能力分开实现和验证 |
| 执行者 | 人工与一种叉车作业档案；货物和资源需匹配 | 机器人档案可演示unknown/不匹配，不填虚假载荷与容差 |
| 原案例 | 复用已确认规则、空腔几何与源身份账 | W02柜高例外、5mm投影承托不能成为新业务的物理默认 |
| 数据入口 | 公司/仓库建模板，司机少量补项并确认 | 语音/OCR辅助不自动得到尺寸、重心与强度 |
| 结论等级 | 吨位/方数只能粗筛；件级资料完整再做3D与动作 | 不把模型近似、测量与实测结果混为一类 |

设备档案字段至少含载荷/质量口径、适配包装/工具、工作范围、禁用条件与来源；未知字段列明影响，不能用“人工兜底”消除所有限制。附件中“≤30kg/≤1.2m共280件”未经本轮数据复算，不进入机器人覆盖率或商业指标。

## 10 政策、通关、费用与加固怎样落地

### 政策和通关

规则绑定国家/地区、道路/港口/具体设施、船司/订舱、货类/柜型、日期和来源；冲突或未知给出责任人/下一步，不套全球默认。国内车型/限行与港口资料是不同适用范围。

中国海关已有货物申报与单一窗口服务，申报涉及实际收发货人/受委托报关企业及材料。首发做字段/装箱单一致性、资料缺项、人工确认和外部状态来源，后续再经授权接接口；不能用本地“确认”代替海关受理/放行。[海关办事指南](https://online.customs.gov.cn/static/pages/guides/000629002001/000629002001.html)、[单一窗口状态查询](https://app.singlewindow.cn/qspserver/sw/qsp/query/view/export)。

VGM核实、SI/进港截止、报关状态、码头/船司状态分别展示。货物/包装/柜号变化后，列受影响的资料和已申报记录供专业人员处理；不自动修改既有申报。海运路线/船期可复用成熟工具，不在首发重建国际航线或船舶导航。

### 费用和处罚

分开列运输/新增绕路、装卸/倒货、等待、加固材料/作业、免费期/滞箱滞期/堆存与行政处罚依据。实际报价、合同、单价、时间/币种口径有来源；缺项显式呈现。不为违规路线计算一个低罚款后将其列为可行候选。

### 加固是作业要求，不只是一句提示

首发支持：①货物/载具需固定的依据；②客户提供的固定方式或材料；③需求来源；④人工确认状态；⑤每次卸货后的余货复核。绑扎带柔性力学不以一个AABB近似冒充完成。

工程计算增强需要运输工况/加速度、摩擦依据、货物/包装/锚点强度、绑扎材料额定值与布置等输入，以及相应计算方法和复核。缺少这些就输出“待工程确认”，不猜需要几条绑扎带。静态稳定、运输抗滑/抗倾覆与材料强度分别评估。[CTU Code加固章节](https://wiki.unece.org/spaces/TransportSustainableCTUCode/pages/23102048/4%2BSecuring%2Bof%2Bcargo%2Bin%2BCTUs)、[CTU Code性质与全文入口](https://unece.org/transport/intermodal-transport/imoilounece-code-practice-packing-cargo-transport-units-ctu-code)。

### 必须出现的验收反例

| 反例 | 应有行为 |
| --- | --- |
| 终态看似可放，中间移出支撑件 | E1指出步骤/余货冲突；不能只看最终图 |

## 13 本轮需要拍板的10项核心决策

愿景、目标用户、陆运优先、3D核心与首发不控机已经明确。D01～D10已根据用户反馈明确产品方向；D07的数据接入条件需要实际验证。

| 编号 | 决策 | 可选范围与取舍 | 建议组合 | 影响 |

## 15 商业验证、来源与评审后动作

优先验证运输公司和独立司机的同一任务：录入＋规划＋复核总耗时、额外动作、误接/误拒、现场返工及原因。海陆协作测重复录入、资料缺项和交接复核；执行者契约测能力/引用/回执错误命中，不能把它称真实机器人成功率。

建议取得至少一家公司、若干合作司机与仓库的可回放样本，覆盖正常任务和有代价的异常；目前访谈/付款未完成。模型收益、客户估计和实际费用分别记录；扣除政策数据、算力、人工建模、规则维护与实施支持后评估毛利。不能把所有等待、货损或改订都归为本产品可节省。
