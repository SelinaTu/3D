# CargoPlan 舱策 · 完整产品方案

> **面向多站点、异形货物的可执行装卸规划 Agent**
>
> v3.0 · 产品全景与功能决策稿 · 2026-10-30
>
> 本稿说明完整产品、各项功能的价值和建议。功能均供负责人选择；建议不代表已批准的范围，规划能力不代表已实现。

## 01 背景、定位与愿景

货运计划同时面对三类问题：**这批货怎么装、这辆车怎么跑、每一站怎么卸。** 三者互相影响：路线改了，卸货顺序就变；嵌套装载提高空间利用率，却可能增加取货动作；装卸设备不同，同一货物的可操作方式也不同。

EasyCargo等产品已经把三维装载、优先组、轴载、人工调整和装载指导产品化。CargoPlan进一步聚焦**复杂货物与全程作业之间的连接**：把货单和业务要求转成一份可修改、可核对、可传给现场及设备系统的运输作业计划。[S1–S4]

**愿景：让货物从接单、装车、运输到最后一站卸完，都有相互一致的计划和作业依据。**

**产品定位：面向货主、承运商与装卸集成商的运输作业规划平台，以Agent为交互入口、三维场景为作业界面、规划与校验引擎为计算核心。**

完整产品输出五件东西：可比较的接单与配车方案、路线与到站计划、货物摆放方案、逐站装卸作业单，以及可供设备系统适配的结构化任务包。不是仅输出装载率，也不是靠聊天模型直接决定货物位置。

### 一个直观的业务场景

一辆车运送去C工地的门窗框，准备顺路接一批去B仓库的辅材。系统需要一起判断：辅材能否放进框孔；B站能否先取出；是否要临时挪货；B站有没有堆区和适配设备；路线是否经过限高桥或限行区域；绕行和搬移之后这单还值不值得接。

用户最终看到的是“方案A可直接卸、方案B需额外搬移、方案C缺许可或设备条件”，并能查看原因和替代方案。计算不确定或数据缺失时显示缺项，不把未知当作可行。

**我的建议：** 优先验证有重复SKU、复杂货物和真实返工成本的企业客户。司机端、平台合作、机器人适配都可纳入完整产品，但不假设它们立即成为收入来源。先证明同一客户反复需要这项服务，再扩客户类型。

市场规模、价格与节省幅度目前未完成客户验证。原案例证明需求存在；竞品说明证明部分边界；它们都不能单独证明普遍付费意愿。

## 03 覆盖哪些货物

“支持一类货物”同时包含几何、承载与作业方式。能画出外形不等于已能为该类货物完成全部运输和装卸计算。

| 货物类型 | 目标产品如何处理 | 客户价值 | 当前基础与建议 |
| --- | --- | --- | --- |
| 纸箱、木箱、规则设备箱 | 长方体，方向、承重、堆叠及保护距离 | 通用基础，可与成熟工具同题比较 | 已有基本模型；建议基础 |
| 托盘与组合包装 | 子货物→托盘→整组搬运，含叉孔和加固占位 | 将规划单位与现场搬运单位统一 | 需要补组合与搬运语义；建议增强 |
| 门窗框、矩形框架 | 同一物件包含实体梁、贯通孔、孔内类别和方向授权 | 利用真实空腔，避免把整框当实心盒 | 已有特定模板；建议重点 |
| 门扇、玻璃及玻璃运输架 | 区分载具与货物，接触/承重面、禁压、保护与搬运设备 | 贴近真实工程物流 | 已有原案例规则子集；需专项验证 |
| 板材、型材、长条包装 | 长件方向、支撑跨距、外廓及进出门路径 | 降低长件静态可放、实际拿不出的风险 | 静态正交外包模型可借鉴；支撑与路径需增强 |
| 多SKU辅材与工具箱 | 同类自叠、单件/累计载荷、最大面向下、孔内适配 | 和主货一起配载，减少尾柜与零散补发 | 已有本批规则子集；建议重点 |
| 圆柱、卷材、管材及圆桶 | 圆柱或经批准的包装模型，加防滚、鞍座及设备条件 | 进入卷材、管件、桶装物流 | 未实现专用防滚/力学模型；可选专项 |
| 不规则机械设备 | 外包络/凸分解/CAD简化体、重心、吊点、禁触面 | 支持高货值设备项目 | 需客户工程数据与专业验证；可选专项 |
| 易碎或精密货 | 禁压面、缓冲、隔离、振动/运输要求 | 降低现场误操作，便于作业交付 | 规则与附件可记录；运输动态需专项 |
| 冷链或危险品 | 温区、通风、不相容性、许可及专业设备 | 服务高要求运输 | 专业规则与资质依赖强；独立专项选择 |
| 袋装、可压缩、散体或液体 | 可变形/填充/液体动力学模型 | 扩大货类覆盖 | 不属于目前模型；需独立引擎，建议单列研究 |

每个SKU记录实际尺寸、重量、重心依据、包装和夹具接触面、允许姿态、支撑条件、设备适配，以及数据来源。新货型按“模板建模→静态反例→动作模拟→设备验证→现场回访”逐级开放。

### 来自原始文件的差异化需求

| 原始要求 | 转化为产品功能 |
| --- | --- |
| W02外部顶部禁放，孔内允许特定辅材/侧放框扇 | 区分外顶与内部授权，框梁和子件建立关系 |
| 不同框孔允许不同类别及方向 | 候选订单适配具体空腔，不仅比较方数 |
| 侧放严格小于120kg、平放限定整垛件数 | 条件规则随姿态变化，分开累计载荷、单件与件数 |
| 辅材上件最大面积面向下 | 计算接触面，而不是把“宽面”猜成固定轴 |
| W02侧放2560mm、通常建模高度2500mm | 区分模型例外、实物内高和门洞，不以备注突破物理硬限 |

原项目为90源行、1371件。现有11柜是冻结模型结果；站点、路线与机器人条件是新业务输入，不能从原货单推定已经存在。[L1]

## 05 路线计算：不是只找最近的一条路

完整产品提供三种可选能力：**固定路线下配载**、**给定路线的可通行检查**、**路线—配车—装卸联合优化**。它们是不同功能，可以分别决定投入；不能用站点动画冒充地图导航或路线优化。

| 计算维度 | 需要考虑什么 | 系统输出 | 关联功能 |
| --- | --- | --- | --- |
| 站点与订单 | 先取后送、订单同车、指定中转、客户安装顺序 | 可行取送顺序和冲突原因 | F10–F12 |
| 空间与操作 | 每个到站状态、门口方向、嵌套、承托、临时堆区 | 位置与动作序列及额外搬移 | F06–F14 |
| 公路通行 | 整车含货高度/宽度、总质量、轴组载荷、桥隧及道路限制 | 可通行候选、换车或绕行 | F14–F15 |
| 地方政策 | 城市、路段、日期/时段、排放/车型/能源类型、许可 | 等待、绕行、换车型或补许可 | F16、F19–F20 |
| 到站作业 | 营业/预约时间、卸货时长、设备/人员、月台及堆区容量 | ETA、服务区间及等待计划 | F05、F13、F17 |
| 人车资源 | 班次、驾驶与休息限制、续航/补能、车辆可用性 | 可执行日程及资源缺口 | F17、F23 |
| 成本 | 路费、油电、人工、车辆、装卸、等待及客户合同迟到费 | 合法可行方案的成本/收益比较 | F18、F22–F23 |
| 动态变化 | 临时封路、订单改变、位置偏差、设备故障 | 新版本与影响说明 | F26 |

**合法和物理可行是约束，成本是其后的比较。** 不把罚款当作交钱即可通行的选项，也不规划规避检查站。路线中一段无法核实政策时显示“待核实路段”，不能标成全程合法。

联合规划的产品策略：地图服务提供路网/ETA候选，CargoPlan增加货物、逐段载荷、取送和装卸代价；必要时把空间校验反馈给路线规划。预算内未找到方案时返回已知可行备选或说明，不能随意宣称全局最优。

### 示例：同一个订单的三个合法备选

| 备选 | 可能的代价 | 为什么有价值 |
| --- | --- | --- |
| 保持车型，绕开受限路段 | 里程增加、到站时间变化 | 避免到场才受阻 |
| 保持路线，等到许可时段进入 | 等待增加，可能影响后续预约 | 让等待成本可见 |
| 拆单或换合适车型 | 增加车辆/换装作业 | 解决不能靠重新摆放消除的限制 |

上述为产品场景，不代表具体城市的实际批准结果。

## 06 地方政策、罚款政策与商业后果

### 政策怎样进入产品

每条政策记录适用地理范围、车型/货物、时间、生效失效日期、官方来源、例外和许可条件、审核人及版本。政策文本由Agent辅助整理，生效条件与参数需要确认；地图或搜索不到不等于没有限制。

| 政策类型 | 产品检查 | 用户看到的价值 |
| --- | --- | --- |
| 城市货车限行 | 路段/区域、时段、车型、排放、通行码 | 发车前选择时段/路线，而非现场碰运气 |
| 限高限宽与载荷 | 整车外廓、桥隧限值、总重/轴载 | 防止“柜内能装、道路不能走” |
| 大件许可 | 不可解体属性、资质、批准时间/路线/速度及护送 | 明确要补什么条件，避免把软件结果当通行证 |
| 行政处罚 | 行为、地区、车型、超限程度及适用条款 | 显示风险范围和依据，不生成罚单或承诺处罚结果 |
| 码头/铁路接收要求 | 有效的称重、偏载、包装及承运条件 | 识别拒收、重新配载和资料缺项 |
| 商业条款 | 预约、等待、堆存、滞箱、迟到、额外搬移 | 与行政罚款分开，按合同计算或标待确认 |

### 有依据的例子

**中国公路超限。** 本次核对的交通运输部2021修正版第43条，对适用总质量超限情形列明：未超过1000kg的予以警告；超过1000kg的，每超1000kg罚500元，最高30000元。第36条要求卸载等消除违法状态，第39条规定不放行违法超限车辆进入收费高速。产品必须同时提示处置后果，不能只给罚款金额；具体认定、取整、其他违法类型及适用裁量另行核实。[S5]

**地方限行。** 通辽公安2026年9月公开提示按路线和时段管理货车通行，并有经“交管12123”申请通行码的要求。它说明政策依赖城市、路段、时间和审批状态，不能用一个全国开关表达。本例仅用于产品设计，不作为其他城市的通行依据。[S6]

**英国超重处理示例。** DVSA现有指南适用于英格兰、苏格兰和威尔士，给出低于10%、10%至低于15%、15%及以上的100/200/300英镑固定罚款梯度，并说明执法余量、严重案件和禁行处置；不能把该表推广为整个欧洲或所有情形的统一罚金。[S7]

**海运VGM。** 核实毛重是相关集装箱装船条件之一；产品可以整理分项重量和资料草稿，不能替代认可的核实方法。拒装、等待和改船费用按实际承运人与码头条款处理。[S8]

中国之外的美国州法、欧盟成员国、铁路站点及港口要求，作为可选规则包逐地核实和维护。仅在输入报告出现的罚金或日期，不直接复制进启用规则库。

**我的建议：** 将“政策约束能定位到具体路线和时间”与“异常后果有依据”作为产品能力；精确罚金额度计算按地区专项开发。评审时可单独选择F16、F19、F20，不需要捆绑整个法律知识库。

## 07 装载与逐站装卸：用户实际拿到什么

计划包含货物位置，也包含每站动作：卸下目标、先移依赖物、临时存放、回装、装入新货、检查余货和确认离站。

| 用户问题 | 产品回答形式 |
| --- | --- |
| 这件货能放哪里 | 三维位置、姿态、框孔授权和影响规则 |
| 为什么拿不出来 | 高亮阻挡物、真实框梁、承托对象和通道 |
| 要挪几次 | 倒货事件、去重件数与额外动作数分开列，来自动作日志 |
| 挪到哪里 | 指定临时堆区及设备，显示容量和占用 |
| 卸完这一站是否还能走 | 余货支撑、重量/轴载、保护与必要运输条件的检查 |
| 修改一件货会怎样 | 受影响站点、约束与任务，保留旧版并重新验证 |
| 哪个方案更值得选 | 同数据比较车辆数、搬移、工时、成本和未决条件 |

物件能通过终点碰撞检查，不等于移动路径畅通；空腔中可放入，不等于设备能夹取。系统需检查路径扫过的实体、先后依赖和剩余货物，而非只将装车动画倒放。

建议用户可选“车辆数优先”“少倒货优先”“估计成本优先”等策略。权重和硬约束显式展示，不把偏好写成物理限制；没有最优性证明时使用“预算内最好已找到方案”。

## 08 面向未来的双臂友好装卸协议

按最新附件，将“双臂”纳入正式产品方向：**CargoPlan提供版本化作业任务契约，让人工、单臂、双臂、叉车和集成商有一致的货物与任务语义。** 它是产品接口设计，不自称国际标准。

双臂已有生产部署信号：FedEx与Dexterity在2026年7月公布扩大Hagerstown拖车装载部署，涉及双臂Mech及自主装车决策。因此我们的价值应是跨订单/跨站及客户规则的上游协调，而非声称机器人没有自主规划。[S9]

### 任务包要说明的内容

| 内容 | 对设备/集成商的价值 |
| --- | --- |
| 货物ID、包装、质量、重心及禁触面 | 知道搬什么、哪些信息可靠 |
| 起点、目标、坐标系、单位和完整姿态 | 避免位置和侧放方向歧义 |
| 动作、依赖、站点及前置条件 | 知道何时可以执行、必须先完成什么 |
| 单臂/双臂候选、设备profile和能力校验 | 提早标出人工可做而该设备不适配的货物 |
| 双臂角色、协作组、共同载荷与释放条件 | 将同一物件的协同搬运表达为一个任务组 |
| 候选接触区域、进入方向、环境与物体包络 | 给设备侧抓取和运动规划提供已知信息 |
| 临时堆区、回装与现场状态 | 支持倒货和异常恢复，不只支持顺利路径 |
| 验证等级、版本、确认、执行/失败回执 | 确认实际状态后再继续，避免重复或失效任务 |

### 双臂协作需要单独表达的约束

- 区分两臂各搬一件、两臂共同搬同一件，以及一臂扶持一臂操作；不能只用一个“有两条臂”的开关。
- 双臂额定协同载荷由设备确认，不能用单臂额定值直接相加；臂展、姿态、夹具、重心和受力也影响可行性。
- 共同持物要保持两接触点与物件的约束；从双臂切换为单臂或释放前需确认承托与稳定。
- 只有设备侧抓取、运动及控制验证后才能执行；静态AABB包络不能证明两臂运动无碰撞。
- 单臂设备可以忽略不适用的展示字段，但不能忽略“必须双臂”或其他必需能力；不兼容则阻断或返回人工方案。
- 低可靠度抓取信息必须进入待确认；不能根据重量猜一个抓取点后直接标记可执行。

### 与现有协议如何连接

| 层次 | 协议/框架 | CargoPlan怎样对接 | 准确边界 |
| --- | --- | --- | --- |
| 企业订单和作业系统 | REST/JSON，按伙伴需要gRPC/Protobuf | 创建计划、取作业包、状态回执 | 是接口技术，不是装卸行业标准 |
| 状态与异常事件 | MQTT | 任务、设备和现场事件回传 | 不直接承担关节实时控制 |
| 固定设备/PLC | OPC UA或伙伴协议 | 门开、输送线就绪等前置条件映射 | 需具体设备信息模型与联调 |
| 移动底盘/车队 | VDA 5050 | 经适配器关联底盘移动订单和状态 | 官方当前3.0面向移动机器人，不是双臂抓取协议 [S10] |
| 多品牌AMR共存状态 | MassRobotics AMR互操作接口 | 对接已确认版本的能力及位置状态 | 本次核对的1.0说明以观察/共享为主，不当作完整任务标准 [S11] |
| 机械臂规划/执行 | ROS 2、MoveIt、ros2_control或OEM接口 | 由集成商将任务转换为设备侧规划与执行 | 框架能力不等于已完成某台设备适配 [S12] |

推荐数据契约统一SI单位m/kg/rad/s、右手坐标系、完整姿态、schema版本与能力协商。现有内部mm模型在明确的导出边界转换；不同坐标系必须给出变换，不能只改名称。协议破坏性变更即使在0.x也要可检测并拒绝不兼容任务。

**我的建议：** 选择F31时，先完成语义、Schema及可回放任务样例；选择F32时再指定设备与协议版本做适配。两者分开计工作量和报价。是否实际控机，由你后续确定合作设备和验证范围。

## 09 用户界面与实际使用流程

完整界面建议保留六个工作区，避免把所有技术概念同时堆给用户：

| 工作区 | 主要内容 | 一次操作的结果 |
| --- | --- | --- |
| 订单/车次 | 货单、候选订单、车型及状态 | 创建一次规划任务 |
| 规则/资源 | 客户要求、货物、车辆、设备和政策 | 确认本次适用条件与缺项 |
| 路线/成本 | 地图、站点时间、政策影响及备选 | 选择要计算或比较的候选 |
| 三维装卸 | 车内布局、站点时间轴、依赖与临时区 | 审阅、编辑、复核方案 |
| 作业交付 | 人工作业单、设备任务包及现场确认 | 下发某一已确认版本 |
| 运营复盘 | 偏差、耗时、倒货、费用和规则记录 | 找到实际改善及可复用经验 |

Agent侧栏随当前任务提供解释和指令入口，不替代主界面的结构化信息。政策详情、协议字段及算法日志按需展开。

一次完整操作：导入订单→补齐资源→确认规则→规划路线与装卸→比较方案→改动与复核→发布作业版→现场回执→偏差重算→复盘。

界面区分“已通过”“缺数据”“需确认”“不适配”“未找到方案”。静态布局、简化动作、设备仿真、现场验证分别显示等级；未完成的检查不显示通过。

## 10 商业化方案与建议

### 谁为哪种结果付费

| 产品服务 | 收费选择 | 客户购买理由 | 商业依赖 |
| --- | --- | --- | --- |
| 企业复杂订单审单 | 按方案/项目 | 更快出具可解释计划 | 每单人工工作量可控 |
| 调度与作业工作台 | 团队/站点订阅 | 经常性的少返工、少倒货、协作和经验沉淀 | 重复SKU与持续使用 |
| 路线/政策专项 | 按地区/模块或企业包 | 对实际运营地区提供可靠检查 | 持续维护、地图数据及专业审核成本 |
| 企业规划API | 调用量/容量/SLA合同 | 嵌入已有订单和WMS/TMS系统 | 接口权限、稳定性及采购流程 |
| 机器人接口与设备适配 | 实施+维护或联合项目 | 减少业务计划与设备之间的集成重复工作 | 设备试点、责任分工与可复用适配器 |

建议将基础产品、地区维护与设备集成分别核算，避免一份廉价订阅包含无限定制。规则库跨客户复用需要授权，不能默认将客户数据变成公共资产。

收益测量关注真实的规划工时、返工/搬移、等待、临时增车和履约质量；没有实际减少支出时，释放工时与现金节约分开报告。处罚暴露可以展示，但不承诺具体“省罚款金额”。

现阶段没有已验证定价、市场规模或客户收入。建议以真实业务回放、同题竞品试用及付费试点判断投资价值，而非用社交媒体检索量替代需求量。

### 我的产品建议，供你选择

1. **价值主线：** 复杂货物、多站作业与可追溯规则的联合规划。
2. **最有辨识度的组合：** F02/F07/F10/F13/F24/F28——备注变规则、框孔授权、逐站倒货与3D解释。
3. **接单商业链：** F15–F18/F22，使“可装载空间”变成考虑路线与作业成本的可接订单。
4. **未来接口链：** F05/F29–F32，使设备差异、双臂语义和现场回执可逐步接入。
5. **资源依赖较重：** 全国实时政策、危险品、大规模车队联合优化、通用CAD和真实双臂控机，应分别评估数据与合作方投入，不在没有资料时打包承诺。

以上是建议组合，不是替你定的首版范围。你可以在功能清单中独立选取。
