# CargoPlan 舱策：完整产品方案

> 面向多站点、异形货物的可执行装卸规划 Agent
>
> 版本：评审稿 v2.0 · 2026-10-30 · 面向 ClawHunt 与后续商业试点
>
> 决策建议：先做工程物流的人工作业指导，再验证人机协同；通过可重放的作业过程建立产品价值。

## 01 一页决策摘要

CargoPlan 将货单、客户备注、取送站点和设备条件，转成有出处的规则、可检查的货物布局、逐站装卸动作及可追溯作业清单。第一批用户是有重复 SKU 和复杂装卸要求的门窗、家具及工程物流调度团队。

**核心价值主张：装得进去，按站取得出来，修改后还能核对。**

| 评审问题 | 本方案回答 |
| --- | --- |
| 解决什么问题 | 框体空腔、条件承重和取送顺序叠加后，静态摆放方案可能无法按计划作业；备注理解及现场改动难复核 |
| 为什么从这里切入 | 原始门窗案例具有明确的空腔授权、方向和承重条件；EasyCargo 的公开几何模型限于长方体 |
| 产品创新在哪里 | 将规则来源、货物实体/空腔关系、逐步装卸依赖和设备条件贯穿到一个版本化计划中 |
| MVP 必须做什么 | 一车三站、20–40 件、至少一个真实框孔模板；规则确认→规划→逐步验证→3D回放→改单→作业单 |
| Agent 承担什么 | 提取待确认规则、解析改动、调用规划与验证工具、解释有来源的结果 |
| 如何商业化 | 先向调度负责人提供收费试点；验证节省超过录入、维护、实施与服务成本后，再扩展订阅及企业接口 |
| 如何对接机器人 | 先输出仿真任务草案及设备适配结果，待设备侧确认、仿真和现场联调后进入执行 |
| 目前完成到哪 | 已有原始数据解析、部分框孔模板、静态布局校验、3D和离线报告；多站动作规划和完整Agent闭环尚待开发 |

**本轮评审要定的三件事：** 首批客户聚焦工程物流；核心演示必须同时覆盖框孔和站点；法规/地区规则包不挤占核心闭环开发。建议主报 Agent，3D 与商业化共同支撑；正式赛道及旧代码、案例素材复用范围以主办方确认结果为准。[E10]

## 02 愿景与产品边界

长期愿景是让货物从装车到最后一站卸完，每一步都有明确的作业条件、依据和结果反馈，使人工、叉车和机器人系统能够围绕同一个计划协作。

这里的“可执行”分四级，而非一个未经区分的绿色对勾：

| 等级 | 含义 | 本次能够承诺的范围 |
| --- | --- | --- |
| L1 静态布局校验 | 清单完整、几何、方向及声明的静态载荷条件通过 | 复用已有经验；仍须保留具体模型假设 |
| L2 简化动作校验 | 在指定出入口、搬移路径和支撑模型下逐步回放通过 | MVP 的开发目标，不能提前标为已实现 |
| L3 设备仿真校验 | 加入设备本体、夹具、抓取/插叉、姿态与运动限制 | 与设备集成商联合验证的后续目标 |
| L4 现场验证 | 实测货物、设备和作业环境中完成试验及回执 | 付费试点阶段验证；不由动画替代 |

首期“异形”限定为矩形框、已知贯通空腔、长件与箱体混装。任意 CAD 曲面、散体、可变形货物和通用机器人控制不进入首期承诺。站点顺序作为输入；全国路线和时间窗联合优化属于后续能力。

## 03 真实需求与证据分级

证据分为原始案例事实、官方能力说明、所提供调研的线索和待验证假设。缺少公开功能说明不等于竞品无法提供企业定制；社交样本也不等于付费需求或市场规模。

| 需求 | 依据与准确语义 | 产品处理 |
| --- | --- | --- |
| W02 框顶禁放、孔内可放辅材或侧放框扇 | 门窗第16行及备注；外部顶部和孔内是不同关系 | 同一货物 ID 绑定实体梁、空腔授权、内载及外顶载 |
| 不同孔允许不同货物 | 门窗21行短框仅辅材，23行长框允许辅材/侧放框扇 | 空间容量随货物类别、方向而变，不仅输出剩余方数 |
| 分姿态限重与自叠 | 原表存在侧放严格小于120kg、平放堆数及同源要求 | 条件规则随姿态切换；区分总载荷、单件及整垛计数 |
| 上件最大面积面向下 | 辅材28–43行及用户确认 | 根据上件几何计算，不把“宽面”固定为某个原轴 |
| W02 高2560与通常2500上限冲突 | 原备注允许突破摆放限制；实际柜高/门洞未因此得到证明 | 建模例外和实测硬边界分开；物理硬限不得由备注覆盖 |
| “尽量靠柜门” | 原表软偏好 | 不升级为绝对禁放条件；记录未满足原因和代价 |
| 多站点及设备条件 | 原始文件没有实际多站取送表、机器人及抓取面 | 新增业务输入；演示站点明确标成派生场景 |

项目背景为90个源数据行、1371个物理单元、134777.37kg。既有11柜结果通过冻结模型的复核，尾柜模型实体体积由39.3122降至35.5820m³；这不是实际运输验证、10柜证明或全局最优证明。外包盒体积、扣确认空腔后的模型实体体积和实际材料体积不能混用。[I3][I4]

现有数据有实际高度例外、5mm竖直间隙及投影承托的边界。新演示优先使用实测适配的示例车辆和明确的承托条件，不借用这些未核实项制造更好指标。

所提供X样本报告自述去重1204条、其中157条强相关有机线索；本次未取得原始页逐条复核，不将这些数字视为客户数、需求比例或已完成访谈。[I5]

## 04 EasyCargo 产品对标

EasyCargo已经覆盖录入、容器选择、规则分组、计算、人工修订、报告及共享。我们需要达到完整工作流的基本可用性。[E1]

| 维度 | 官方公开情况 | CargoPlan 的选择 |
| --- | --- | --- |
| 数据与业务交付 | Excel、基础约束及计划输出成熟 | 做到可导入、可修改、可保存、可传给现场 |
| 原生几何 | FAQ明确支持长方体，其他形状尚不支持 | 先完成框体/空腔模板，不扩张为通用异形引擎 [E2] |
| 多站卸货 | 优先组先装后卸，并可控制组间分离 | 承认已有能力，增加逐动作遮挡及余货检查 [E3] |
| 人工修改 | 支持吸附、自动旋转及批量移动；手工调整不保证全部业务限制 | 新版本须显示哪些约束通过、失效或待复核 [E4] |
| 修改反馈 | 重量统计刷新；尺寸和限制变化需按说明重装或重算 | 显式记录影响范围，不把统计刷新当作计划有效 [E5] |
| API | 公开API传输入、取结果，计算仍需登录应用发起 | 提供Agent可调用的异步求解和验证任务 [E6] |
| 公路车辆 | 已有轴载及重量分布功能 | 不能宣称轴载独有；按车型补齐而不以重心代替 [E7] |
| 多柜 | 公开流程可继续放置余货，单轮最多10份报告 | 不误写为永远只能算10柜；跨柜效果需同题实测 [E8] |

术语修正：EasyCargo 的 multi-pickup 是编辑器批量选取/移动多件货物，不是沿途多站提货。[E9]

对于逐动作稳定性、复杂框孔授权、机器人夹具约束等，公开资料没有完整支持证据，应标为“待实测”，不能写成全部不支持。国内装箱大师、悠闲装箱、智火也已具备不同程度的顺序、修改和重算能力；仅对官方明示边界作确定判断。[I6]

## 05 客户、作业流程与购买理由

| 优先级 | 客户与购买者 | 使用者 | 需要验证的价值 |
| --- | --- | --- | --- |
| 首批 | 有重复SKU和工程货的专线/小车队调度负责人、制造企业物流经理 | 计划员、仓库主管、装卸班组 | 备注是否减少漏项，是否减少返工、倒货及临时加车 |
| 第二批 | 货代、项目物流服务商 | 操作主管、客户经理 | 方案是否更快交付，是否更容易与客户和仓库对账 |
| 后续 | WMS/TMS及机器人集成商 | 系统与设备工程师 | 任务接口是否适配真实流程，实施是否可重复 |
| 渠道合作 | 大车接单平台及企业订单系统 | 产品与调度团队 | 接单可行性结果能否改善履约；需授权接口和采购验证 |

首次进入以已有客户订单/CSV为输入，不依赖抓取平台或自动抢单。平台是未来渠道和接口合作对象；独立工具应先证明单客户价值。[E11]

用户旅程：创建车次与站点→导入货物→确认规则和缺项→设置设备/作业条件→生成方案→逐站审阅→修改与复核→下发作业单→现场确认状态→必要时重新规划。

收货方按楼栋/楼层/安装顺序交付是可探索的业务需求，但原表的楼层标签不足以证明客户已经要求多站到货，应在访谈中独立确认。

## 06 产品模块与页面方案

| 页面/模块 | 用户任务 | 关键交互与交付 |
| --- | --- | --- |
| 车次与站点工作台 | 创建固定线路及当前车内状态 | 站点顺序、装卸清单、取送时间、待装/已装/在途/交付状态 |
| 货物及设备库 | 维护可复用SKU、框孔和设备模板 | 实测尺寸、材料/包装、允许姿态、出入口、抓取/插叉条件、来源及版本 |
| 规则确认台 | 看懂备注并确认 | 原文与单元格、结构化解释、影响货物、确认人；未知条款不能静默丢弃 |
| 方案比较台 | 选择可接受的计划 | 柜车数、完整性、倒货、工时、未知项和等级；比较同一规则集 |
| 3D作业工作台 | 看每站每一步 | 当前目标、阻挡物、临时堆区、支撑关系、回退与重算入口 |
| 接单评估台 | 判断追加订单代价 | 几何/动作/设备条件、增量成本、未决项及所需改动 |
| 作业交付台 | 将方案给现场与系统 | 装车/卸货单、任务草案、扫码或人工回执、偏差记录、版本 |
| 规则包管理 | 维护客户及地区条件 | 适用范围、来源、生效日期、审批、自动或人工检查、停用状态 |

3D承担解释空间和操作过程的工作；货物及设备的尺寸来自参数和实测，不能以生成式美术模型替代。生成的车辆或机械臂外观只作展示资产。

## 07 Agent 与规则证据链

确定性解析货物身份和数值；LLM抽取备注中的待确认条件，解析用户修改并解释结果；求解和校验工具负责坐标、依赖关系与指标。解释中出现的数字必须来自本轮工具结果。

规则经历：提取→待确认→已确认→启用→新版本变更或停用。模型自报置信度只作审阅提示，不是统计正确率；首期所有影响硬约束的新抽取规则均需确认。未识别语句保留原文并阻止将受影响范围标为全部通过。

示例为目标数据结构，并非当前系统已具备：

```json
{
  "ruleId": "R-frame-cavity-01",
  "source": {"sheet": "门窗", "row": 16, "column": "AM", "text": "空腔内放框扇时框扇必须侧放"},
  "scope": {"sourceSheet": "门窗", "sourceRow": 16},
  "kind": "cavity.childOrientation",
  "condition": {"childSourceSheet": "门窗"},
  "value": {"verticalOriginalAxis": "width"},
  "status": "pending_confirmation",
  "version": 1
}
```

“非自身相同物品”按已确认的物品身份/SKU语义处理，不随意扩大成“同一大类全禁”。客户内部规则只在授权范围复用；跨客户规则库需去标识和授权，不能默认共享。

Agent工具建议：`import_manifest`、`extract_rule_drafts`、`confirm_rules`、`plan_trip`、`validate_plan`、`simulate_stop`、`assess_order`、`export_workpack`。任何实物动作、订单发布与接单仍经业务系统明确确认。

## 08 空间、货物及状态模型

单位为mm、kg。原点位于车厢远离门的一侧左下角，X正方向指向柜门，柜门在X=L；Y沿宽度、Z向上。简化卸货沿 **+X** 朝门移动，装货反向；修正旧提案中“X指向门却沿-X卸货”的矛盾。

每件货物具有唯一ID、源表/行、实际尺寸重量、允许姿态、取送站点、实体几何、空腔及授权关系。框梁是同一货物的组成部分，不分别作为可独立移动的物件。姿态含侧放信息，任务接口使用完整旋转表示，不只记录yaw。

每个状态包含：车内货物位置、已装/已卸/临时移出清单、临时堆区占用、承托/嵌套关系、已完成动作、在用规则版本、实测与计划偏差。每件货满足取货站先于送货站，库存只能通过合法动作变化。

载重与重心须按出发的每段状态重算；动作中移走支撑件前先处理受支撑对象。运输阶段需检查对应车型轴载/加固等条件，不能由车厢重心阈值代替。缺少车型轴参数时显示未评估。

MVP几何采取已批准的箱体/矩形梁组合和贯通孔模板，限制正交姿态；路径为单门直线平移。设备本体、夹具及关节轨迹暂不进入L2结论，缺少相关条件时不授予L3。

## 09 逐步装卸与倒货定义

阻挡检测检查货物沿提取路径扫过的实体体积，而非只看终点或外包盒。框孔需区分真实梁与空白；空间通行与支撑依赖分别处理。

候选动作包括装入、卸下、临时移出、回装、确认偏差。允许倒货时，临时场地也必须有尺寸、承重、可用性和已占用物件；无堆区或设备条件不能凭空假定可放地上。

| 指标 | 本方案统一定义 |
| --- | --- |
| 倒货事件 | 非本站交付货物为完成本站操作而临时移出；同一物件同站重复移出分别计事件 |
| 倒货件数 | 某站发生倒货的不同货物ID数；全程另报按站累计值及全程去重值 |
| 额外搬移动作数 | 由动作日志实际计数；完整的一次移出+回装通常为2次，不一概用件数乘2 |
| 阻挡件数 | 当前状态下的直接/递归阻挡数，不等于最小倒货数 |
| 工时估计 | 每个实际动作的配置耗时之和，含设置/找位/等待参数；缺少实测时标为假设估计 |

先生成依赖图，再搜索可执行动作序列；存在循环或无法满足的路径时返回具体约束及未知项。递归清除阻挡只是启发式，不能称为最少倒货证明。不能只倒放装车动画来宣称卸货可行。

每步动作前后检查：目标存在及取送资格、空间路径、承托关系、临时区域、库存一致性。动作完成后再检查余货静态条件，运输离站前补检查重量/平衡及必须满足的运输条件。

## 10 求解目标、状态与服务架构

先满足清单和已启用硬约束，再优化。固定一车MVP使用字典序：完整可行→倒货事件→额外动作/估计工时→空间效率。跨车商业版由用户选择“车辆数优先”或“估计成本优先”，记录策略版本，不把多个互相冲突的优先级同时称为成本最低。

成本模式纳入车辆、里程、停靠、装卸及搬移等有依据的费用。新订单收益以当前可行计划为基线计算增量；货损缺数据时列风险项，不编造概率和收益。

初始构造采用目的站逆序分区+组内极点法；已确认框孔生成合法嵌套候选。逐站仿真找到冲突后，采用局部交换、重摆、合法姿态及候选嵌套调整，在预算内保留最好可行解。中途取货作为后续P1，必须在真实到站状态新增，不能提前把新货放进前段车厢。

比较基线包括同约束的团队实现“优先组+构造式装载”及人工已有方案。前者是代理基线，不是EasyCargo真实输出；不得故意破坏基线后宣称优于竞品。竞品对比需要单独试用留存输入和结果。

服务拟用React/TypeScript/Three.js前端，Web Worker或Node执行规划，异步API负责长任务。具体模型供应商可替换，不把活动赠送额度视为长期成本。输出状态区分：缺少输入、规则待确认、已找到可行解、超时未找到、被证明不可行、已完成验证。只有有确定证据或求解器证明时使用“不可行”。

复核按独立入口从规范化源清单及动作日志重算，不只信任候选的valid字段。初期共享几何原语时如实说明，不声称算法实现完全独立；关键语义用反例和后续不同实现交叉验证。

## 11 机器人与企业任务接口

机器人已有自主感知和现场规划能力，不以“机器人没有大脑”作为前提。CargoPlan提供跨订单、跨站和客户规则的上游计划，需现场系统确认实际位姿与设备能力。门框不自动适配面向纸箱的卸货机器人。[E12]

```json
{
  "schemaVersion": "0.1-draft",
```

## 12 地区规则包与多式联运

保留下载报告提出的规则包方向，但放在核心产品之后。规则包作为可维护内容：每条有来源、生效日期、地区/运输方式、输入要求、核验方法及负责人；未经核实的规则不得启用自动通过结论。[I1]

| 方向 | 可以规划的功能 | 当前证据及优先级 |
| --- | --- | --- |
| 客户私有作业规则 | 包装、支撑、装卸、留证清单 | 首批试点核心，逐客户确认 |
| VGM分项草稿 | 货件、托盘、垫木、固定材料、皮重清单 | IMO已说明相关称重方法；产品草稿不能替代认可的验证流程，后续P2 [E13] |
| CTU检查项 | 装载/固定作业核对及证据附件 | IMO说明其为非强制全球实践准则；不能把所有建议写成普遍硬法，P2 [E14] |
| 公路轴载 | 车型、轴距及适用路段条件版本化 | 已有竞品支持；按试点地区专项核实后开发 |
| 铁路偏载、木包装及口岸作业 | 条款来源与客户书面要求 | 输入报告中的具体数值/实施日期本次未逐条核实，不进入默认规则集 |
| 危险品 | 专业规则与隔离条件 | 不纳入首期；不沿用“危险品一律近门”等过度概括 |

不以未经证实的“每个港口都有独特几何规则”构建卖点，也不以规则包宣称完成认证。

## 14 开发工作包与里程碑

| 包 | 内容 | 前置依赖 | 完成条件 |

| P0-2 | 矩形框/孔、方向及授权模板 | P0-1 | 内外关系反例通过，不只绘制框外观 |
| P0-3 | 基线构造与静态校验 | P0-1/2 | 完整清单或明确未装列表，已启用规则可核对 |
| P0-4 | 单门动作、临时堆区和余货检查 | P0-3 | 从日志重放后得到同一终态 |
| P0-5 | Agent规则确认与改单工具 | P0-1/3 | 不确定条款可见，解释引用工具结果 |
| P0-6 | 3D时间轴、对比与导出 | P0-3/4/5 | 同数据端到端可运行，回执结构可读 |
| P1-1 | 局部改进及中途取货 | P0完整 | 不改变既定过去状态，超时保留可行方案 |
| P1-2 | 设备、轴载、执行反馈 | 试点参数与数据 | 有明确适配范围、反例及现场确认 |

## 15 验收与同题竞品测试

| 项 | 验收要求 |
| --- | --- |
| 清单身份 | 每件从输入到在车/堆区/交付状态闭合；无消失、重复或提前出现 |

## 16 商业模式与验证计划

商业假设：先销售“复杂订单规划与复核”，再依使用频率采用按方案或团队订阅，后续提供企业API与实施。机器人任务接口作为联合试点，不作为首期收入来源承诺。

EasyCargo官网公开月付79美元/用户、年付799美元/用户，日票9.7美元且至少10张，均未税。这为通用工具提供价格参照，不是本产品已经验证的定价。[E15]

| 收费方式 | 适用条件 | 验证重点 |
| --- | --- | --- |
| 按次复杂订单审单 | 低频、有明确复杂需求 | 每次是否需要大量人工；可否形成重复模板 |
| 团队订阅 | 稳定SKU和频繁多站作业 | 月度价值、持续使用、支持与数据维护成本 |
| 企业API/实施 | 订单/WMS流程已确定 | 集成权限、采购周期、复用率及SLA成本 |
| 设备联合试点 | 有具体货型、夹具和现场 | 设备侧验收范围、付费责任及实际作业改善 |

每客户月贡献=实际收费−模型与计算−人工复核支持−数据维护−实施摊销。避免用无限人工定制包装成高毛利SaaS。

访谈至少5家目标客户，取得至少3家可回放样本，并争取至少1个付费试点。以上均为目标，不是已完成数量。记录规划耗时、倒货动作、临时加车、设备/场地条件、现有软件及采购预算。多班次现场结果与同题竞品数据一起决定继续投入。

收益测算示例仅供访谈：100单/月×每单净节约80元=8000元/月。每单节约必须扣除新增搬移、等待和维护成本，不能把空闲工时自动当成现金节约。这不是报价、客户成绩或市场统计。

停止或转向条件：问题不能重复、没有必要输入、复杂规则都需逐单人工重写、竞品同题无明显差异，或节省不足以覆盖总成本。市场规模不从X检索量推算，待明确ICP后按目标客户、发运频率及预算自下而上估计。

## 18 整合取舍、来源与评审问题

本方案保留原提案的Agent证据链、逐站回放和商业试点路径，吸收下载报告的设备分层与规则包方向；用EasyCargo新核对结果修正竞品边界。主要取舍如下：

| 原材料中的分歧或问题 | 本稿处理 |
| --- | --- |
| 框孔是P2，但定位强调异形 | 一个已确认框孔模板提升为P0；通用CAD仍后置 |
| 下载报告强调规则包、原提案强调作业 | 多站异形作业为主线，地区规则为可扩展模块 |
| 倒货件数、动作数混用 | 分开计事件、去重件数和日志动作 |
| 坐标指向门而卸货方向相反 | 统一门在X=L，简化取货为+X |
| 同类禁放被扩大成类别禁放 | 使用源身份或确认SKU语义，不擅自扩义 |
| 竞品“未见”写成不支持 | 仅官方明示边界记为确定，其余待实测 |
| 国内规则、铁路阈值及日期直接落地 | 未核实条款不进入启用规则集 |
| 单纯高置信度即自动生效 | 首期硬规则提取须确认，未知不静默通过 |
| 现有经验与参赛新成果混用 | 单独列状态、时间及复用授权问题 |
