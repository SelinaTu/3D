## 00 愿景与核心能力

**愿景：做运输作业规划的智能体，让货物从接单、配载、运输到每一站装卸，都有相互一致、可核对、可执行的作业依据。**

四项核心能力，构成产品的主张：

| 核心能力 | 一句话 | 为什么是我们 |
| --- | --- | --- |
| **C1 多站装卸规划** | 卡车多站与国际港口多点的装载序、倒货、逐站可取与逐段稳性 | 竞品多为单次装载或线性分组，少有逐站倒货计数与逐段校验 |
| **C2 异构异形货物装配** | 门框等带空腔、分姿态、条件承托的工程货，不止长方体 | 主流工具默认纸箱托盘；异形与条件约束是公认短板 |
| **C3 双臂装卸友好** | 输出版本化作业任务契约，人工、叉车、单臂、双臂共用一套语义 | 机器人进入装卸后，方案成为执行接口；提前留出语义 |
| **C4 港口政策辅助** | 限重限量结合罚款政策，给出绕行、等待、换车、补许可等运营策略 | 把"装得下"延伸到"走得到、卸得掉、罚不着" |

Agent 是交互入口（理解规则、调用工具、解释结果），三维场景是作业界面，确定性规划与校验引擎是计算核心。**不是仅输出装载率，也不是靠聊天模型直接决定货物位置。**

### 能力之间如何咬合

四项能力不是四个独立模块，而是一条作业链上的四个环节：

```
接单/配载 ──C2 异构装配──▶ 车内/柜内布局
    │                           │
    │                     C1 多站装卸序
    ▼                           ▼
C4 港口/路线政策 ◀── 逐段车辆状态 ── 逐站作业单 ──C3 执行契约──▶ 人/叉车/机器人
```

一个改动会沿链传导：路线变了，卸货序就变；嵌套装载省了空间，却可能增加取货动作；某港限重，就要在配载阶段提前分配重量。产品的价值正是把这条链上的相互影响一次算清，而不是让用户在四个工具之间手工搬运结果。

## 01 背景与真实案例

货运计划同时面对三类问题：**这批货怎么装、这辆车/这个柜怎么走、每一站怎么卸。** 三者互相影响，却被切在不同工具和不同人手里：装箱软件算满柜，地图软件找路线，报关和船代各管一段，现场班组凭经验执行。衔接处的信息丢失，就是倒货、返工、滞港和罚款的来源。

EasyCargo、装箱大师、悠闲装箱、packVol 等已经把三维装载、优先组、轴载、人工调整和装载指导产品化。[S1–S4, S10] CargoPlan 不在"算满一个柜"上竞争，而是聚焦**复杂货物与全程作业之间的连接**。

### 一个验证用的真实案例（伊拉克 Villa）

团队手上有一份真实工程货清单：门窗、玻璃架、辅材三张表，90 源行、展开 1371 件、约 134.8 t、590 m³。它的价值是**证明 C2 异构装配的难点真实存在**，不是产品只服务门窗出口。清单里这些要求，主流工具的表单装不下：

| 清单原文（节选） | 对产品的意义 |
| --- | --- |
| W02 框外顶禁放，孔内允许辅材或侧放框扇 | 实体梁、空腔、内载、外顶载要分别建模，不能用一个外包长方体 |
| 短框孔仅允许辅材，长框孔允许辅材或侧放框扇 | 空间不是任何货都能用，余量随类别和方向变化 |
| 玻璃架只能承托"非自身相同物品"，顶部 ≤600 kg | 反向条件承托，常规"是否承重"字段表达不了 |
| 辅材"上件最大面积面朝下" | 要算接触面，不能把"宽面"猜成固定轴 |
| W02 侧放 2560 mm、通常建模 2500 mm | 区分模型例外、实物内高和门洞，不以备注突破物理硬限 |

> 复核记录见 `MODEL_CALIBRATION_REVIEW.md`、`W02_ROW16_REVIEW.md`。该案例此前完成过单站点配载研究（1371 件装入、独立校验通过），**多站、路线、港口和设备条件是新增业务输入，不能从原货单推定已经存在**。把它改造成多站样例时必须标为演示扩展。

### 异构货物的范围

C2 的"异构"指产品要覆盖一个谱系，而不是单一货型。能画出外形不等于能完成该货型的全部装卸计算，每类货按"模板建模 → 静态反例 → 动作模拟 → 设备验证 → 现场回访"逐级开放，货型清单与开放节奏见第 04 章。Villa 的门框、玻璃架、辅材分别落在这个谱系的"框架""载具+货物""多 SKU 小件"三档。

## 02 谁使用、解决什么问题、为什么付费

| 客户/角色 | 日常问题 | 产品价值 | 付费/采购主体 |
| --- | --- | --- | --- |
| 货主：门窗、家具、设备等制造企业 | 异形、承重、包装细则依赖经验，出货变更难复核 | 沉淀 SKU 与规则，减少人工反复排柜及现场返工 | 企业物流经理、项目负责人 |
| 承运商：工程物流、专线、零担车队 | 多站倒货、追加订单、车型与线路难一起判断 | 接单前评估可行性和增量成本，司机与仓库共用一份计划 | 调度主管、车队经营者 |
| 货代、仓库与装箱服务商 | 要向客户解释方案、向班组交付、向码头交资料 | 快速审单、出方案、作业指导、VGM 草稿、版本与责任依据 | 货代操作主管、仓库负责人 |
| 装卸集成商：WMS/TMS、机器人与自动化 | 业务订单与设备任务之间要转换和校验 | 提供上游货物语义、顺序、位姿、条件和异常事件 | 企业项目采购或集成商 |
| 司机和装卸班组 | 不知道先拿哪件、现场不一致怎么办 | 手机作业单、逐步定位、异常反馈 | 通常是使用者，不预设司机个人订阅 |

**三个付费锚点（参数待访谈填入，不预设金额）：**

1. **少用一个柜/一辆车** = 省一程海运费加拖车费。货量接近整柜时最敏感。
2. **避免一次现场返工** = 省掉掏箱重装的工时、设备和误船/误期风险。
3. **多接一单** = 车上剩余空间转成边际收入（承运商侧，收入价值比成本价值好卖）。
4. **避免一次罚款/拒收** = C4 港口政策的直接价值，但要和商业等待费分开表达，不承诺"省罚款金额"。

市场规模、价格与节省幅度尚未完成客户验证。原案例证明需求存在，竞品说明证明部分边界，二者都不能单独证明普遍付费意愿。商业验证门槛见第 10 章。

"支持一类货物"同时包含几何、承载与作业方式。下表的"当前基础与建议"供你决定开放节奏。

| 货物类型 | 产品如何处理 | 客户价值 | 当前基础与建议 |
| --- | --- | --- | --- |
| 纸箱、木箱、规则设备箱 | 长方体，方向、承重、堆叠及保护距离 | 通用基础，可与成熟工具同题比较 | 已有基本模型；**基础** |
| 托盘与组合包装 | 子货物→托盘→整组搬运，含叉孔和加固占位 | 规划单位与现场搬运单位统一 | 需补组合与搬运语义；**增强** |
| 门窗框、矩形框架 | 同一物件含实体梁、贯通孔、孔内类别和方向授权 | 利用真实空腔，不把整框当实心盒 | 已有特定模板；**重点（C2 招牌）** |
| 门扇、玻璃及玻璃运输架 | 区分载具与货物，接触/承重面、禁压、保护与搬运设备 | 贴近真实工程物流 | 已有原案例规则子集；需专项验证 |
| 板材、型材、长条包装 | 长件方向、支撑跨距、外廓及进出门路径 | 降低"静态可放、实际拿不出"风险 | 正交外包模型可借鉴；支撑与路径需增强 |
| 多 SKU 辅材与工具箱 | 同类自叠、单件/累计载荷、最大面向下、孔内适配 | 与主货一起配载，减少尾柜与零散补发 | 已有本批规则子集；**重点** |
| 圆柱、卷材、管材及圆桶 | 圆柱或经批准的包装模型，加防滚、鞍座及设备条件 | 进入卷材、管件、桶装物流 | 未实现专用防滚/力学；可选专项 |
| 不规则机械设备 | 外包络/凸分解/CAD 简化体、重心、吊点、禁触面 | 支持高货值设备项目 | 需客户工程数据与专业验证；可选专项 |
| 易碎或精密货 | 禁压面、缓冲、隔离、振动/运输要求 | 降低误操作，便于作业交付 | 规则可记录；运输动态需专项 |
| 冷链或危险品 | 温区、通风、不相容性、许可及专业设备 | 服务高要求运输 | 专业规则与资质依赖强；独立专项 |
| 袋装、可压缩、散体或液体 | 可变形/填充/液体动力学模型 | 扩大货类覆盖 | 不属目前模型；需独立引擎，单列研究 |

每个 SKU 记录实际尺寸、重量、重心依据、包装和夹具接触面、允许姿态、支撑条件、设备适配，以及数据来源。

**建议：** 首批深做"门窗框 + 门扇玻璃架 + 多 SKU 辅材"三类（恰好是 Villa 案例覆盖、且证据最全的组合），长件和托盘作增强，其余按客户专项开放。

## 05 C1 多站装卸规划：卡车多站与港口多点

多站是本产品的第一招牌能力。竞品已有"按组顺序/优先组"做到多站**装载序**（EasyCargo 优先组、悠闲 VIP 按组装载、packVol 纵向优先组 [S2, S10]），所以差异不在"支持多站"，而在**把多站算到可执行**：

| 竞品普遍做到 | CargoPlan 要做到的差异 |
| --- | --- |
| 按目的地分组，先装的后卸 | 逐站**算出倒货次数**：哪件挡了哪件、要挪几次、挪到哪个临时区（F13） |
| 校验装完那一刻的重心 | **逐段校验**：每卸一站后，剩余货物的支撑、重心、轴载重新算（F14） |
| 全部货在起点装 | **中途装卸混合**：B 站卸一部分、再装新货进腾出的空间，且不挡后站货（F12） |
| 线性站点顺序 | 多个**合法站点顺序**并给出各自代价（少绕路 vs 少倒货，F11） |
| 终点无碰撞即可 | 取货**路径**扫过的实体、先后依赖、剩余稳定都要查，不只把装车动画倒放 |

### 两种多站形态

- **卡车多站**：一车多个提货/卸货点，路线、时窗、地方限行一起算（接 C4）。
- **港口多点**：一柜/一票货经中转港、目的港多段，每段的 VGM、限重、查验要求不同（接 C4 的港口规则包 F21）。两者共用同一套"逐站状态 + 逐段校验"内核，只是约束来源不同。

### 用户实际拿到什么

| 用户问题 | 产品回答形式 |
| --- | --- |
| 这件货能放哪里 | 三维位置、姿态、框孔授权和影响规则 |
| 为什么拿不出来 | 高亮阻挡物、真实框梁、承托对象和通道 |
| 要挪几次 | 倒货事件、去重件数与额外动作数分开列，来自动作日志 |
| 卸完这一站是否还能走 | 余货支撑、重量/轴载、保护与必要运输条件的检查 |
| 改一件货会怎样 | 受影响站点、约束与任务，保留旧版并重新验证 |
| 哪个方案更值得选 | 同数据比较车辆数、搬移、工时、成本和未决条件 |

策略可选"车辆数优先""少倒货优先""估计成本优先"等，权重和硬约束显式展示；没有最优性证明时用"预算内最好已找到方案"，不写"全局最优"。

## 06 C4 港口与路线政策：限重限量 + 罚款 → 运营策略

这是你确定要做的核心能力。采用**混合深度**：客户主航线的 3–5 个核心港做到精确（限值、罚款档位可测算），其余港与路段做风险提示（标注"待核实路段"，不假装全程合法）。

### 政策如何进入产品，如何控制维护成本

每条政策记录：适用地理范围、车型/货物、时间、生效失效日期、官方来源、例外和许可条件、审核人、版本。政策文本由 Agent 辅助整理，生效条件与参数需人工确认。**地图或搜索不到，不等于没有限制。**

维护成本的控制办法：

1. **路网/ETA/限高限重路线交给地图服务**（高德货车导航、路网 API 等），CargoPlan 只提供地图没有的那一半——**根据剩余货物输出逐段车辆状态**（总重、轴组载荷、车货总高宽长），喂给地图或 TMS 判断能否通行（F15）。
2. **罚款与限值只对核心港/地区精确维护**，其余引用全局 fine_profile 并标风险。
3. **港口规则包做可配置 checklist**，按客户开通的航线按需建档，不预先铺满全球港口。

### 政策检查与价值

| 政策类型 | 产品检查 | 用户看到的价值 |
| --- | --- | --- |
| 城市货车限行 | 路段/区域、时段、车型、排放、通行码 | 发车前选时段/路线，而非现场碰运气 |
| 限高限宽与载荷 | 整车外廓、桥隧限值、总重/轴载 | 防止"柜内能装、道路不能走" |
| 大件许可 | 不可解体属性、资质、批准时间/路线/速度及护送 | 明确要补什么条件，不把软件结果当通行证 |
| 行政处罚 | 行为、地区、车型、超限程度及适用条款 | 显示风险范围和依据，不生成罚单 |
| 港口限重限量/VGM | 核心港 cutoff、No VGM No Load、偏载、称重方式 | 识别拒收、重新配载和资料缺项 |
| 商业条款 | 预约、等待、堆存、滞箱、迟到、额外搬移 | 与行政罚款分开，按合同计算或标待确认 |

### 有依据的例子（2026-10-30 核对原文）

- **中国公路超限** [S5]：交通运输部 2021 修正版第 43 条，车货总质量超限未超 1000 kg 的予以警告；超过 1000 kg 的每超 1000 kg 罚 500 元，最高 30000 元；外廓超限另有 200–3000 元档。第 36 条要求卸载消除违法状态，第 39 条规定不放行违法超限车辆进入收费高速。产品必须同时提示处置后果，不能只给金额。
- **地方限行** [S6]：通辽公安 2026-09-05 起主城区货车限行，分绿/红/黄三类路线时段，需经"交管 12123"申请通行码。说明政策依赖城市、路段、时间和审批状态，不能用一个全国开关表达。
- **英国超重** [S7]：DVSA 固定罚款 £100/£200/£300 三档（<10% / 10%–<15% / ≥15%），通常给 5% 执法宽限，超 1 吨以上不给宽限。不能把该表推广为整个欧洲。
- **海运 VGM** [S8]：SOLAS VI/2 修正，2016-07-01 生效，核实毛重是装船条件之一。产品可整理分项重量和资料草稿，不替代认可的核实方法；拒装、等待和改船费用按承运人与码头条款处理。

### 同一订单的三个合法备选（产品场景，非具体城市批准结果）

| 备选 | 可能的代价 | 为什么有价值 |
| --- | --- | --- |
| 保持车型，绕开受限路段 | 里程增加、到站时间变化 | 避免到场才受阻 |
| 保持路线，等到许可时段进入 | 等待增加，可能影响后续预约 | 让等待成本可见 |
| 拆单或换合适车型 | 增加车辆/换装作业 | 解决不能靠重新摆放消除的限制 |

**合法和物理可行是约束，成本是其后的比较。** 不把罚款当作交钱即可通行的选项，不规划规避检查站。

> 港口广度清单（P0 22 个、P1 35 个的建档优先序）见 `CLAWHUNT_PORTS_P0_P1.md`。MVP 只精确做 3–5 个核心港（建议 Shanghai、Ningbo、Rotterdam、Los Angeles 四选三），其余为 checklist + 风险链接。港口附件中"中国海事局 VGM ±5% 或 1 t"一项**来源为船司指引，写入规则库前需找到官方原文**。

## 07 装载与逐站装卸：执行层的产品回答

计划不止是货物位置，还包含每站动作：卸下目标、先移依赖物、临时存放、回装、装入新货、检查余货、确认离站。

物件能通过终点碰撞检查，不等于移动路径畅通；空腔中可放入，不等于设备能夹取。系统要检查路径扫过的实体、先后依赖和剩余货物，而非只把装车动画倒放。倒货不是失败态，是一等的 `relocate` 任务，带临时堆区坐标。

界面区分"已通过""缺数据""需确认""不适配""未找到方案"五种状态。静态布局、简化动作、设备仿真、现场验证分别显示等级；未完成的检查不显示通过。

## 08 C3 双臂装卸友好：执行契约（首发到"任务契约 + 人机同序"）

### 首发边界（已定）

首发做到两步，不接真机、不做设备联调：

1. **版本化作业任务契约**：输出带坐标系、序号、动作、位姿、依赖、能力要求的任务数据。
2. **人机同序**：同一份 `sequence`，既能渲染成给人看的手机作业单（F25），也能导出给设备读。叉车司机和装卸班组是**第一个消费者**，机器人是后续。

双臂字段（`arm_role`、`requires_dual_arm`、`sync_group_id`、`collision_envelope`）在 schema 中**预留**，首发不联调。这样 C3 愿景完整，投入可控。

### 为什么现在就留双臂语义，而不是现在就控机

- **趋势真实**：FedEx × Dexterity 的双臂 Mech 拖车装载 2026-07 从试点扩产，其 Foresight 世界模型自己优化包裹摆放。[S9] 说明双臂装车已在量产边缘。
- **但近期不靠它吃饭**：机器人越普及，上游越需要确定的顺序、位姿和逐步可行性。人能容忍"大概这么放"，机器人不能——这正是任务契约的长期价值。
- **边界清楚**：没有感知、抓取点、夹具、轨迹规划和功能安全，任务数据只用于仿真和接口讨论，**不控制机器人**。`status: simulation-only` 是固定字段。

### 分层心智模型（产品必须画清）

```
[CargoPlan 规划层]  plan + stops + rules + sequence + envelopes + 可选双臂提示
        │  任务草案（JSON，未来可选 Protobuf）
        ▼
[集成/舰队/WMS 桥接]  REST·gRPC 任务创建 · MQTT 事件 · OPC UA 门禁/输送线 · VDA 5050 底盘订单
        ▼
[运动/操纵 OEM]  ROS 2 MoveIt + ros2_control 或 UR/ABB/Fanuc 专有
        ▼
[安全/认证控制器]  ← CargoPlan 永不越界
```

### 对接主流协议的准确边界（2026-10-30 核对）

| 协议 | 管什么 | 对 CargoPlan 的准确关系 |
| --- | --- | --- |
| REST / gRPC | WMS↔任务系统事务型创建 | MVP 首选外向契约，不做实时关节控制 |
| MQTT | 轻量发布订阅、遥测 | 任务状态/异常回传 |
| OPC UA | 固定设备、PLC、门、输送线 | "门开/线体就绪"映射为前置条件 |
| VDA 5050（3.0.0，2026-03 发布 [S-VDA]） | 舰队主控↔移动机器人（MQTT+JSON） | **不是双臂抓取标准**；底盘进柜时相邻，可挂 `amr_order_ref` 占位 |
| MassRobotics AMR Interop（1.0，2021-05 [S-MR]） | 多厂商 AMR 状态共享 | **明确把机械臂排除在范围外**；仓内共存监测，与装柜弱耦合 |
| ROS 2 / MoveIt / ros2_control | 中间件、运动规划、轨迹控制 | 伙伴消费我们的包络和位姿，我们不跑 MoveIt |

**柜内/拖车装卸任务的机器可读标准目前几乎不存在**（公开检索未见 IMO/ISO 级 schema）。CargoPlan 自建版本化 schema，并声明非行业法定标准。

扩展字段（`arm_role`、`sync_group_id`、`collision_envelope`、`grasp`、`motion_hint`）见 `CLAWHUNT_ROBOT_PROTOCOL_DUALARM.md`，首发仅预留不联调。版本策略：`0.x` 可删可选字段；`1.0` 起 `frame`/`sequence`/`preconditions` 锁定必填。

## 09 界面与 Agent 入口

### 六个工作区（供计划员细查和调整）

| 工作区 | 主要内容 | 一次操作的结果 |
| --- | --- | --- |
| 订单/车次 | 货单、候选订单、车型及状态 | 创建一次规划任务 |
| 规则/资源 | 客户要求、货物、车辆、设备和港口政策 | 确认本次适用条件与缺项 |
| 路线/成本 | 地图、站点时间、政策影响及备选 | 选择要计算或比较的候选 |
| 三维装卸 | 车内/柜内布局、站点时间轴、依赖与临时区 | 审阅、编辑、复核方案 |
| 作业交付 | 人工作业单、设备任务包及现场确认 | 下发某一已确认版本 |
| 运营复盘 | 偏差、耗时、倒货、费用和规则记录 | 找到实际改善及可复用经验 |

### Agent 作为主入口（建议）

目标客户（中小货主、专线车队、货代）日常在微信、企业微信、飞书群里传 Excel，不一定会专门打开规划软件。建议 Agent 不只是侧栏，而是**低门槛入口**：

- 用户把订单 Excel 发给企业微信/飞书机器人；
- Agent 回规则确认卡片（原文、出处、置信度），用户确认；
- Agent 返回方案链接、作业单和缺项提示；
- 现场异常在群里回传，触发重规划。

工作区保留给需要细查和拖拽调整的计划员。这样 Agent 赛道/能力的叙事自然，渠道上也和传统装箱软件区分开。

**Agent 的设计红线：** LLM 只做三件事——把自然语言转结构化规则、把用户指令转结构化改动、把结果翻译成解释。坐标、可行性、指标全部由确定性代码计算。LLM 产出必须过 JSON Schema 校验，不合格回退"待人工确认"，不静默丢弃。解释中的数字只能引用求解器输出。

一次完整操作：导入订单 → 补齐资源 → 确认规则 → 规划路线与装卸 → 比较方案 → 改动与复核 → 发布作业版 → 现场回执 → 偏差重算 → 复盘。

## 10 商业化与验证

### 谁为哪种结果付费

| 产品服务 | 收费选择 | 客户购买理由 | 商业依赖 |
| --- | --- | --- | --- |
| 企业复杂订单审单 | 按方案/项目 | 更快出具可解释计划 | 每单人工工作量可控 |
| 调度与作业工作台 | 团队/站点订阅 | 经常性少返工、少倒货、协作、经验沉淀 | 重复 SKU 与持续使用 |
| 港口/路线政策专项 | 按地区/模块或企业包 | 对实际运营走廊提供可靠检查 | 持续维护、地图数据、专业审核 |
| 企业规划 API | 调用量/容量/SLA | 嵌入已有订单和 WMS/TMS | 接口权限、稳定性、采购流程 |
| 机器人接口与设备适配 | 实施+维护或联合项目 | 减少业务计划与设备之间的重复集成 | 设备试点、责任分工、可复用适配器 |

悠闲装箱企业每天免费 2 箱，说明按装柜次数收费空间很小，应按"项目"或"价值"定价。基础产品、地区维护、设备集成分别核算，避免一份廉价订阅含无限定制。规则库跨客户复用需授权，不默认把客户数据变成公共资产。

### 规模化风险与应对

每客户规则要人工确认，容易变成"每单定制"的服务生意。应对：**按行业沉淀规则模板**，先做门窗幕墙一个行业，用"新客户首单的确认工作量是否下降"判断模板是否起效。若只能靠每单人工定制，不应按可规模化 SaaS 估值描述。

### 验证门槛（投资/继续投入前必须过）

1. 访谈至少 5 家目标客户，取得至少 3 家可回放业务样本，分别记录人工耗时、现场搬移、临时加车、货损、装卸设备现状；
2. 通过同约束的竞品试用（悠闲、EasyCargo、packVol）发现可重复差异；
3. 至少一个客户愿意进行有费用的试点；
4. 单客户节省高于订阅、数据维护、人工确认与实施总成本。

测算示例（仅访谈测算，非市场统计）：每月 100 单、每单净节约 80 元 = 每月 8000 元价值。参数待访谈填入，不宣称已有收入。

### 北极星指标

建议用**"方案首次执行即成功的比例"**（现场无需返工重排）。它同时反映 C1 倒货算得准、C2 约束没漏、C4 政策没踩，是四项能力共同的结果，也最贴近客户感知的价值。

### 市场规模（建议自底向上，不编总量）

按细分数客户：中国门窗幕墙/钢构出口企业数、工程物流专线数、目标客户平均月单量。访谈中校准，不用社交媒体检索量替代需求量。
