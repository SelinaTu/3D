## 约束解释与人工确认范围

- 解析全部非空工作表，动态查找表头，不假定表头位于第 4 行。未知工作表、缺失必要字段或非法数值会报告工作表名和行号，整次导入失败，不静默丢弃记录。
- 方向字段：立放/正放 → `standing`；侧放/侧立 → `lying`；平放 → `flat`；不限 → 全部。原文“倾斜”不在正交装箱方向集合中。
- 朝向竖轴按数据来源明确区分：原工作簿有“门窗编号”的行使用 `standing → length / lying → width / flat → height`，即门窗平放时包装厚度为竖直高度。源表第 16 行 W02 框包装尺寸 3030 × 2560 × 160 mm，备注明确“侧放后高度2560mm”，与此映射一致。架、辅材及通用模板默认 `standing → height / lying → width / flat → length`。映射作为每件货物 `orientationVerticalAxes` 保存，导出实际占用尺寸，避免标签相同而竖轴混淆。
- “正放，底部”编码为 `standing` 且 `mustBeOnFloor: true`。
- 条件承重仅在相应方向生效，例如侧放顶部总重量严格小于 120 kg；“平放不超过 10 件”将支撑件本身计入整堆，编码为该支撑件上方最多 9 件。
- 顶部单件最大重量、顶部总重量、不可叠放、同原始货物可叠放、不同原始货物可叠放分别保留为可执行规则。同物品通过原始工作表/行或等效物品属性识别，不能仅靠“框”“扇”等宽泛分类。
- 16 行、32 件辅材要求其上方货物“宽面向下”。用户于 **2026-10-16** 明确该语义为“上件自身面积最大的面朝下”，据此编码 `constraints.supportedItemsLargestFaceDown: true`，由装箱与独立校验器强制检查。该条件已有可执行定义，不再标为人工确认。其它未知硬约束仍会标记 `requiresManualReview`，阻止未经确认的货物自动装入。
